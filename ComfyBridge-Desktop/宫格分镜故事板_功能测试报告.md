## 六、联调中发现并修掉的问题

### 1. 0 张参考图时任务被 ComfyUI 整条拒收

现象：创作台不传参考图直接发送，卡片立刻红色失败，原始报错

```
prompt_outputs_failed_validation / node 470 LoadImage
image - Invalid image file: ballet_dancer_photography_minimalist_architecture.png
```

原因：参考生图工作流的 `470 LoadImage` 上写着 ComfyUI 里早就没有的默认图片名。有参考图时第 1 张会改写这个节点，所以问题只在「0 张」时暴露。

修复：`WorkflowRegistry.build_prompt()` 增加 `placeholder` 参数，`services._run_job()` 在「故事板 + 0 参考图」时先 `ensure_blank_image()`（上传一张 1536×864 纯白 PNG，固定文件名只存一份）再填进 `470`。提示词里不引用这张图，出图效果与调试阶段一致。修复后 1/3/4 号用例全部正常出图。

### 2. 「看完整提示词」面板在服务端忙时不出现

现象：机器负载高时点开预览，面板要等服务端组装完才第一次渲染；组装慢于 1.2 秒时，测试会看到「点了没反应」。

修复：`#sheetPvBtn` / `#boardPvBtn` 改成「先重绘一次（面板以『正在组装提示词…』占位）→ 等结果 → 再刷新内容」，面板永远先出现；对应 E2E 断言也从固定 `sleep` 改成等元素出现。

顺带修掉更早的一处前端 bug：`boardForm()` 每次调用都会重建 `cells` 数组，导致 `boardForm().cells[i] = 值` 写进临时数组、逐格输入永远存不住。改成「只有格子数变化时才重建」。

### 3. 宫格按钮被撑成 122px 高

现象：第一版逐格选择器里，没写字的格子用了 `class="board-cell empty"` 表示空白态，结果整排按钮每个高度变成 122px，把表单顶下去一大截。

原因：`web/index.html` 里 `.empty` 是全局空态面板样式（`.empty{padding:60px 24px}`），被复用到了小按钮上。

修复：空白态类名改为 `blank`（`.board-cell.blank:not(.on)`），并给 `.board-cell` 显式补 `padding:0 4px`，避免以后再被别的全局 `padding` 波及。

### 4. 改了 `web/app.js` 但浏览器仍在跑旧脚本

现象：修完逐格输入后刷新页面，行为还是旧的；清缓存重启浏览器才生效。

原因：静态资源走 FastAPI `StaticFiles`，浏览器按默认启发式规则缓存了 `app.js`。

修复：`app/main.py` 加一个轻量中间件，对 `/static/*` 一律回 `Cache-Control: no-cache`（协商缓存，不禁止缓存但每次回源校验）。测试侧同时加固：E2E 每次用「端口号命名的新 profile」启动 Edge，并加 `--disk-cache-size=1`、连上后 `Network.setCacheDisabled`，不再依赖 `Page.reload`（它和启动时的首页加载存在竞态，会偶发 `Cannot find default execution context`）。

### 5. 进程还在、端口不再监听（页面「连不上服务」）

现象：反复跑 E2E 之后，`run.py` 进程活着、日志也没报错，但浏览器访问 8190 直接连不上。

原因：Windows 上 uvicorn 默认用 `ProactorEventLoop`，高频建连/断连时 `IocpProactor.accept` 抛 `OSError: [WinError 64] 指定的网络名不再可用`，把接受连接的协程带走，端口从此不再 accept。这个异常不冒到主循环，所以进程看起来「很正常」。

修复：`run.py` 改为 `_SelectorConfig(uvicorn.Config)`，覆写 `get_loop_factory()` 返回 `asyncio.SelectorEventLoop`。用 400 并发请求压测验证（383 个 200、17 个 ReadTimeout、0 个连接错误，压测后端口仍在监听）。

### 6. 「跑完了但一张图都没有」被记成了成功

现象：ComfyUI 校验不通过时（模型名对不上，见 §九），它照样回一条 `status_str=success` 的历史，只是 `outputs` 是空的。`_finish_success` 会把这条历史当成成功写下去：任务卡片绿勾、`files` 为空、点开什么都没有。排查时特别误导——「成功了却没图」比直接报错难查得多。

修复：`_finish_success` 在收集完输出后加一道判断，一个文件都没有就转成失败态：

```python
if not files:
    self._finish_error(job, run, err(
        "NO_OUTPUT", "ComfyUI 跑完了，但一张图都没产出",
        "多半是工作流里的模型/节点在本机 ComfyUI 里对不上；看 ComfyUI 控制台日志确认",
        short="没有产出图片", retriable=True))
    return
```

单测（stub 掉归档与记录写入）确认：传空 `outputs` 进去，`run.state` 变 `failed`、`err.code` 是 `NO_OUTPUT`；正常出图路径不受影响，重跑 `board_e2e --gen` 仍 44/44、`smoke` 41/41。

## 八、已知限制

- **九宫格每格分辨率偏低**：整图 1536×864 切 3×3，每格约 512×288（四宫格 768×432、六宫格 748×417）。要更高清单格细节就把版式换成四/六宫格，或把整图尺寸调上去（模型对长边有限制，实测 2.0MP 附近已接近上限）。
- **六宫格必须是宽幅**：3 列 × 2 行且每格 16:9 只能是 8:3，所以它有独立工作流副本；这条工作流的 `aspect_ratio` 仍留在工作流里但不参与尺寸计算（宽高直接写死），档位表里它被列为「版式定」。
- **跨格一致性靠参考图 + 文字**：0 参考图时程序用 `no_ref_lock` 段强制同一主角，但这只是提示词约束，不是身份编码；人物特征越具体（发型、服装、标志物）越稳。有参考图时只有写了「图 N」的格子才会被声明为同一身份。
- **空白格依赖模型遵守**：提示词从三段（版式硬约束、单格空白句、收尾）反复强调「纯白、无边框」，实测四/六/九宫格都稳定，但极端复杂提示词下仍可能画出一条淡线，属于模型侧概率问题。
- **整行/整列都留空时，成图看起来像「缺一排/缺一列」**：格子之间刻意不画边框，空白格与白底同色，所以一块连着的空白区和画布留白没法区分。实测 `job_2999`（九宫格，第 3 格/6 格/9 格为空，即第 3 列整列空）成图是 3 行 × 2 列内容 + 右侧整片白；`job_3006`（四格全写）则精准铺满整张画布。要一眼看出宫格结构，就别让整行或整列空着——创作台提示文案已写明这点。
- **格子不是像素级等分**：模型按「2×2 / 3×3 等分」大体对齐，实测内容区与理论网格有十几个像素的偏差（`job_3003` 上排两格宽度 765 / 624，理论各 768）。需要严格等分就后处理裁切，本版没做。

## 九、一次环境事故与恢复

第三轮要验证「重启服务后任务记录还在」，我图省事用了 `taskkill /IM python.exe /F` 收进程，把同名的 ComfyUI 进程一起杀掉了（ComfyUI 也是 python 起的）。排查时发现本机有两套 ComfyUI，这才是真正需要记下来的：

| 目录 | 版本 | 模型来源 | 说明 |
| --- | --- | --- | --- |
| `D:/ComfyUI-0.37.1/ComfyUI` | 0.38.0 | 自己的 `models/`，且 `extra_model_paths.yaml` 的 base_path 指向不存在的 `I:/ComfyUI2026/...` | 模型列表里**没有** `qwen_image_2.1_turbo_int8_convrot.safetensors` |
| `D:/ComfyUI-Desktop/Comfy-Desktop/ComfyUI-Installs/ComfyUI (1)\ComfyUI` | 0.42.1 | 共享目录 `ComfyUI-Shared\models`（turbo 模型在这），输出目录指到 `D:/ComfyUI-0.37.1/ComfyUI/output` | **平时在跑的就是这套** |

第一次误用前者启动，任务被 ComfyUI 拒收，日志是

```
Failed to validate prompt for output 461:
* UNETLoader 459_451:
  - Value not in list: unet_name: 'qwen_image_2.1_turbo_int8_convrot.safetensors' not in [...]
Output will be ignored / Prompt executed in 0.04 seconds
```

表现很坑：ComfyUI 侧「执行成功」，任务卡片显示 `done` 但 `files` 为空——因为归档时拿不到任何输出文件。这一轮里 `board_e2e --gen` 的「成品尺寸」「归档到能力目录」两项就是这时候挂的。

恢复做法：用 `ComfyUI (1)` 的 venv 启动，`--output-directory` 与 `--input-directory` 都指到 `D:/ComfyUI-0.37.1/ComfyUI/output`，模型路径用临时 `--extra-model-paths-config`（`ComfyUI-Shared\models` + 本地 `models` 两段）。起来后 `/system_stats` 报 0.42.1、`UNETLoader` 能看到 turbo 模型，重跑 `board_e2e_test.py --gen` 44/44、`board_gen_matrix_test.py` 10/10，出图正常。

两条教训：

1. **收进程一律按 PID 收**（`netstat -ano | grep :8190` 取 PID → `taskkill /PID`），绝不按进程名批量杀。
2. **生成失败要看 ComfyUI 日志，不能只看任务状态**：`done` + 空 `files` 就是「模型/节点没对上」的典型症状。已经按这条把这种情形改成明确的失败态（见 §六 第 6 条）。

顺带还揪出一个进程卫生问题：重启验证中途发现 8192 端口上还挂着一个重复的桥接实例（早先几次启动尝试留下的子进程，主进程报错退出、子进程活着）。它内存里是一份旧任务列表，任何一次状态变更都会把 `state.json` 覆盖回去，表现为「重启后少了两条记录」。按 PID 清掉后，内存与磁盘的 `jobs` 数量一致。**同一份 `state.json` 只允许一个进程写**，起服务前先确认 8190 没被占用。
