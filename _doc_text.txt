第 01 章
产品定位与边界
一、这是什么
一个跑在本机的"转接台"
把人话（或 AI 的指令）翻译成 ComfyUI 能执行的动作，再把结果翻译回人能看的东西
它和你已有的两个东西的关系：
ComfyUI
它已经会跑了：
管模型、管显卡、跑节点
但只有"节点图"这一种输入方式
必须已经启动
本应用
它补的是"最后一公里"：
人话 → 挑工作流 → 填节点
盯进度 → 取成品 → 说人话
一个进程，一份配置
WorkBuddy 等
它负责"听懂人话"：
理解你要干什么
把结果放回聊天窗口
只发 3 类请求就行
类比：ComfyUI 是一台"会干活但听不懂人话"的机器，WorkBuddy 是一个"听得懂人话但手很慢"的助手。本应用就是中间那个"车间主任"——听一句指令，立刻分配机器、装好参数、盯着干完、把成品端出来。
二、为什么要多这一层（核心论据）
你说的"WorkBuddy 直连 ComfyUI 也行，但太慢"，这个判断是对的。我把"慢在哪"画出来：
方案 A：AI 直连 ComfyUI（每一格都是一次"AI 想一遍 + 等一遍"）
列工作流目录
读 json 看懂节点
问有哪些模型
核对文件名
写脚本改 json
跑脚本
提交（可能报错重来）
等 2 秒
查进度
等 2 秒
查进度
…又查 5 次
解析结果路径
复制文件给用户
合计 15~40 次调用，光"想 + 等"就 1 到 4 分钟，显卡还没开始干活
方案 B：经本应用（只有三格，其余全在本地进程的内存里瞬间完成）
① 看菜单
"你会做什么"
② 下单
"画一只橘猫"
③ 取货
"好了吗"
中间发生的一切（挑工作流、填节点、
盯进度、取文件、翻译报错）
都在本地进程里，毫秒级完成
不算显卡，纯粹"准备 + 等待"
1 ~ 4 分钟
而且每一步都可能出错，出错还要重来，
用户看到的是"一直在转圈"。
还会在磁盘上留一堆临时脚本和 json。
不算显卡，纯粹"准备 + 等待"
1 ~ 3 秒
失败只有几种，原因说得清；
不留任何临时文件，不碰对方目录。
用户体验 = 豆包：写完点发送，等图。
2.1 一句话总结
把"准备和等待"从 AI 的推理循环里，挪到本地进程的内存里。
本机做这些是毫秒级，AI 做这些是秒级。这就是全部价值。
三、边界：一件事只归一个人管
ComfyUI 的活
· 装模型、换模型
· 装自定义节点
· 显卡够不够、跑多快
· 显存怎么分配
· 节点怎么连线
· 模型文件放哪
· 生成质量好不好
· 配额、队列调度
本应用对此的态度：
不打听、不干预、不代劳。
出问题就把它的原话转达。
本应用的活
· 把"人类参数"变成"节点参数"
· 按输入自动挑工作流
· 提交、盯进度、取成品
· 排队、取消
· 把报错翻译成人话
· 两个页面（创作台 / 管理台）
· 给 AI 的接口和技能
· 记住每一次生成的结果
不做：模型管理、性能优化、
显存调优、自动修节点、
读写 ComfyUI 的任何文件。
AI 客户端的活
· 听懂用户想要什么
· 把"下雨的东京"变成提示词
· 判断该用哪个能力
· 把结果放进聊天窗口
· 和用户多轮沟通
不做：
不读工作流文件、不连 8188、
不拼节点结构、不写脚本。

第 06 章
加一个工作流的清单
这张清单可以打印出来贴显示器旁。每加一个工作流，从上往下走一遍，10 分钟内能完成。
全章的核心只有三句：先勾节点（哪几个参数节点给人调）；再填值加档（点添加 = 复制一份工作流）；默认档永远是原始工作流，碰都不碰。 节点是从工作流里读出来的，不是固定的。
一、五步流程图
1
ComfyUI 里
把工作流在 ComfyUI 里跑通，然后"导出 API 格式"
在 ComfyUI 界面里调到你能接受的效果，出图稳定后再导出。别在没跑通的时候就导。
⚠ 用"保存(API格式)"，不是普通的"保存"。普通格式导出的是界面布局，程序读不懂。
2
配置 + 管理台
在 config.yaml 里把它挂到能力下，回管理台确认节点读出来了
把 json 放进工作流目录，在配置里写上文件名；保存后重启服务，再点这个能力的「配置」。左边应列出所有节点：编号 + 类型。
⚠ 列表是空的 → 导错了格式（见第 1 步），或配置里文件名写错。数量对不上 → 检查是不是同一个文件。
3
排档
勾节点 → 排档位，再指定"哪个是成品"
先勾：这个工作流里哪几个节点要跟着档位走（勾中的节点，参数成套进档位）。再排：每档填一遍值。
出片节点和描述框由服务自己认出来，不用你选。没勾的节点原地不动，值照用，用户看不到。
💡 图片类通常勾「尺寸节点 + 采样器节点」；音乐只勾采样节点；语音可能一个节点都不勾。
勾进来的节点只在档位里出现，绝不会单独暴露给用户。
4
真的跑
每一档都试跑一次（不是只试一档）
成功：成品直接显示，并告诉你归档到了哪个路径。不满意就回去改这一档的数值。
失败：页面会说哪一档哪个值越界（例如宽度不是 16 的倍数），改完再跑。
5
保存
保存 → 创作台立刻能用
不用重启。如果这个能力是第一次变可用，创作台里它会从灰色变亮。
二、第 3 步：先勾节点，再加档位
这一步分两小步，顺序不能反。 先决定"这个工作流里哪几个参数节点该给人调"，再决定"加几档、每档填什么"。

二、界面：技术参数不对最终用户暴露
界面上的每一句话都是写给"用它的人"，不是写给做它的人。 这条比下面任何一条都容易违反，所以单列一节（§二之后 2.4）。凡是解释"为什么这么设计""我们刻意不做什么""这是部署信息"的句子，一律搬到需求文档里，界面上一个字都不留。
编号
禁止
原因
X4
禁止在创作台上出现步数、CFG、采样器、种子、Checkpoint 文件名、VAE 名等技术参数
用户看到也不知道怎么选；想调这些的人会直接去用 ComfyUI。管理台的配置区里可以有——那是给配置的人看的
X5
禁止让用户逐个字段打钩凑列（"宽勾一下、高勾一下、步数勾一下"那套）
配置成本高、容易漏勾（勾了宽忘了高就出半吊子状态）。勾的单位是节点：勾一个节点，它的参数成套进来
X6
禁止设计"全项目统一的一套档位"
每个工作流（不是每个能力——一个能力可以挂好几个工作流）的档位都必须单独定。图片和视频的档完全不同，套统一的必然有一半是废话
X7
禁止在创作台上出现"参数映射""节点 ID""字段名"这类内部词汇
用户不需要知道系统内部怎么对应。管理台里字段名可以显示（用小字灰字），因为配置的人需要核对
X7b
禁止在档位之外再给用户留"单独改某一个值"的口子（例如"高级设置""微调步数"）
那就退化成逐个调参数了。要调就把那一档整份拷贝改掉
X21
禁止把"宽 / 高 / 步数 / CFG"写死成固定几列或固定字段
这四个只是文生图常见的组合。音乐工作流没有宽高，绑了加速 LoRA 的工作流只该有步数和 CFG，语音只有音色和语速。写死等于给一半能力配了一堆废参数
X22
禁止在程序里按字段名做特殊判断（例如"如果字段叫 steps 就显示成 X 步""如果叫 width 就自动配 height"）
一旦按名字分支，就等于把字段名写死了。字段名要能随便换、随便加，程序只认"有个字段、它是什么类型、有个值"
X23
禁止给所有能力预置同一套节点/字段模板（"图片模板 / 视频模板 / 音乐模板"这种）
模板看着省事，但工作流一换就全错，还得手动改回来，等于多一层壳。节点只能从当前这个工作流里读出来再勾
X26
禁止把档位做成表格（一档一行，列是参数）
档位是列表：一行一档，只有名字 + 改动项数 +【编辑】+【删除】；点编辑才展开这一档那份拷贝的全部参数。做成表格，参数一多就横向撑爆
X27
禁止让"默认档"可改、可删、可改名
默认档就是原始工作流本身，只读。它存在的意义是给排查一个基准：默认档跑通了 → 问题在某一档的值上；默认档也跑不通 → 问题在工作流本身。一旦允许改它，这个基准就没了
X24
禁止因为"一个节点都没勾"就报错或拦住用户
语音合成这类工作流本来就可能只该有默认档。没勾 = 只有默认档，这是正常状态，不是配置错误。④ 显示空态、④ 的【添加】置灰就够了

2.3 提交与排队：两条路，不许混
编号
禁止
原因
X36
禁止让"普通生成"进队列（发送、再来一张、重试都一样）
普通生成是"马上要看到"的操作。塞进队列就变成盯着一条十几分钟不动的进度条，用户以为坏了。忙就直说忙，比默默排队好一百倍
X37
禁止在 ComfyUI 忙的时候仍然把普通生成提交上去（哪怕只是丢进 ComfyUI 自己的队列）
提交了就算"执行了"，用户会以为马上出片。要求是：忙 → 只提示，不提交、不排队
X38
禁止把队列生成做成"一次只能有一个"（排了一个就不许再排）
队列生成的用途就是批量跑高清。每点一次都要等上一次跑完，那"批量"两个字就没意义了。必须能连着点，排到队尾
X39
禁止让队列生成插到普通生成前面，也禁止在普通任务没跑完时接受队列提交
用户正在等的那一张是"当前的事"，队列是"待办的事"。顺序一反，用户会以为自己的片子丢了
X40
禁止"点了没反应"：任何被拦下的提交都必须说清是哪个任务在跑、跑到几成
只说"系统忙"等于没提示。用户需要知道"哦是刚才那张视频在跑，那我等它"
X41
禁止为队列单独做一个页面（"队列管理""任务列表"那一套）
队列的状态就三处：右栏一行状态、右栏一个清单、结果卡头部一个小标签。为此再开一页，等于承认主界面说不清楚
X42
禁止让【加入队列生成】换种子
队列生成的用途是"这张样片我要高清版"。换了种子就是另一张画，跟用户挑中的那张没关系了。同一批只能有一个种子，一路用到底
X43
禁止在卡片上罗列"共 N 个成品""档位 精细 / 默认"、也禁止贴归档路径
用户看这一批只关心两件事：这张用了什么种子、能不能再来一张。成品数和档位在卡头已有，路径在大图/下载里已有——卡底重复一遍，反而把真正有用的种子挤没了
X44
禁止在管理台提供"添加工作流""新建能力"这类入口（文件选择框、"＋ 新增"按钮、拖进来一个 json 都算）
能力和它挂的工作流是部署信息，只能写在
config.yaml
里。页面上点出来的东西：换个环境就没了、出了事也说不清是哪次点的。页面只做两件事——开/关、排档位
X45
禁止让"没挂工作流"的能力进入可编辑状态
没工作流就没有参数、没有档位，给一张空表单等于让人以为坏了，还会诱使产品去加"添加工作流"的后门。正确做法：列表里显示「未配置」，点进去只有一段说明——告诉人去改配置文件，页面上一个可填可点的控件都没有
X46
禁止除了【加入队列生成】以外的任何入口把任务排进 ComfyUI 队列
发送、再来一张、重试都是普通生成：ComfyUI 忙就只提示、不提交、不排队。队列是给"这张我很满意，出一版更高清的"用的，不能让随手点的发送也挤进去等 5 分钟
X47
禁止让"同时跑几个 / 超时 / 预览帧 / 队列上限"出现在页面上
一次只跑一个、不设超时（本机直连）、不收预览帧——这三件写死在代码里；队列上限写在配置文件里。这些连只读那一行都不必显示：不会变的事实摆在页面上，只会让人以为需要调
X48
禁止做"全局负面词"
没有需要"所有图片共用一段负面词"的场景。负面词就在各工作流自己的格子里，跟别的参数一样进档位表
X49

禁止

禁止在界面上解释"为什么这么设计"（"页面上不提供……是故意的""这一项不能关——归档是固定行为""这里是避免堆满目录"）
用户不关心设计取舍。只说你现在该做什么。反面例：「页面上不给加，因为这是部署信息」→ 正面：「要加工作流，改配置文件后重启服务」

X52

这类句子是写给开发者的约束。界面上要么直接把那个入口去掉，要么用中性陈述代替（"这一档是原文件，改不了"就够了）
X54
禁止一句话里塞两个以上因果链（"因为 A 所以 B，不然 C 会 D，如果要 E 就得 F"）
折成两句短话，或者只留最需要用户知道的那半句。卡片和面板的说明文字，一行不超过 20 个字最舒服
X55
禁止把"原型 / 演示 / 模拟"写进正式界面的按钮和提示里
只有开发自己用的调试入口可以说"演示版不做真下载"；正式交付时这些字样全部清除
X56
禁止让文档里的界面示例和实际画面脱节
文档插图里的每一句话，都必须能在真界面上原样找到。原型改了口径，插图同步改；插图里出现"挂载的工作流（配置文件里）"这种画面上根本没有的区块，开发照着做就会把它造出来——文档插图就是开发眼里的需求
X50~X56 的用法：写界面文案时先问一句"这句话是给用它的人看的，还是给做它的人看的"。后者一律搬进文档，不要留在画面上。改完文案后用敏感词扫一遍页面（部署 / 写死 / 固定行为 / 不给 / 原型 / 来自配置文件 / 设计），有命中就重写。
举一个改到位的例子（结果卡底部那一行）：
改前：「这一批都用这个种子，换档位出来的是同一张，只是更精细」——像在给写代码的人解释机制。

七、一句话总结
这个应用只做一件事：把 ComfyUI 的工作流包装成"会用斜线技能的 AI 能直接点的一道菜"。
界面要极简（描述框 + 档位），配置要极简（选文件 + 勾几个节点 + 填值点添加），存储要极简（单配置文件 + 一堆工作流拷贝），接入要唯一（斜线技能）。
档位里有哪些参数，永远是这个工作流决定的，不是程序决定的（X21~X33）。这一条弄反了，每加一个新工作流都要回来改代码，那就白做了。
配置页只有一件事要做：让用户看清节点、勾出该给用户的那几个、再给它们造几档。 造档的方式是"复制一份工作流"，不是"填一张表"——这样每一档天然就是一份能直接发出去的工作流，不需要运行时再拼。
原始工作流永远是默认档，永远是只读的基准（X27 / X35）。所有"改"都发生在拷贝上。
普通生成忙了就拦住，队列生成才允许堆积（X36~X41）。这两条反过来，用户要么在等一张本该 6 秒出的图，要么得守着一张一张点高清。
一批一个种子，队列只换档位不换种子（X42 / X43）。种子一换，"再来一版高清的"就变成了"再画一张，随便吧"。
任何让上述四件事变复杂的需求，先回到这一章对一遍。

理由
否决的后果

1.05 新增的三条已知问题：
右栏默认只显示最近 120 条任务
：历史超过 120 条时，列表底部出现「加载更早的 N 条」。这样做是因为一次性渲染上千条会把浏览器渲染进程拖崩（实测白屏）。要翻更早的记录，点这个按钮，或去「生成历史」页。
场景设定图-图生图必须写提示词
：后端要求写明"想要的效果 + 从参考图识别出的方位"，只接图不写字会被拒绝（提示「图生图要写提示词」）。画布节点同样受这条限制。
同一条通道一次只跑一个任务
：上一次还没出结果时再点生成会被拒绝，提示「还没跑完」，不会自动排队。等这一张出来再点。
