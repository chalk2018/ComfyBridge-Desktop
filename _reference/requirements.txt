第 00 章1.01 范围与硬约束

本章是 1.01 的硬约束汇总：范围、架构前提、生成方式与队列、种子机制、档位定义、输入区、版本节奏，以及开发交接边界。后文第 01–07 章按功能域展开细节，与本章同为最终口径，按顺序读即可。

功能口径依据：本文件规定「要做什么、按什么规则」，功能口径以本文件为准；界面形态与交互结构以开发原型为主。两者分工不同，不互相覆盖（见 §0.8）。

界面以原型为主：ComfyBridge-开发原型-1.01.html 的布局与交互结构是已确认过的形态，照它实现、不重新设计；本文件不覆盖界面长什么样，也不要求改界面文字与字段。功能口径以本文件为准：状态唯一在服务端、种子由 ComfyUI 生成、档位与母版定义、输入区边界、版本范围按本文件落实。原型里的演示文案与 mock 逻辑是演示形态，照原型保留即可，不用改、也不要照抄成产品行为。

需求边界：只写「要什么」，不核定代码实现。涉及 ComfyUI 自身机制（如种子）时写清事实与约束，具体怎么实现由开发决定。

0.2 全局总原则：状态只有一份，在服务端

这条是架构前提，优先级高于后面所有章节里关于「页面怎么显示」的描述。

状态唯一：正在跑什么、队列里几个、跑到几成、历史出过哪些、配置当前值——全部以服务端为准，只有一份。

判定在服务端：所有 check（能不能发、队列满没满、ComfyUI 连没连上、能力是否匹配）都由服务端算，前端不自己判。

数据在服务端加载：页面刷新、新开窗口、手机访问，都是重新向服务端拉一次当前状态。

前端只做两件事：呈现 + 触发。页面可以开多个，数据状态只有一个。

不做冲突检测：一个窗口在跑，另一个窗口打开必须显示「正在执行」。冲突是「各存一份状态」才长出来的毛病，状态唯一后不需要提示「已被修改」。

手机与 PC 是同一个页面：功能完全一样，只有布局按屏幕尺寸适配，不做独立移动端页面、不裁剪功能。

多端一致不是「补一条提示」，而是把所有判定搬到服务端；前端不做任何跨窗口协调。

0.3 生成方式与队列（1.01 硬规则）

定义：点【加入队列生成】产生的任务叫「队列任务」，除此以外的所有任务都是「普通任务」。生成方式分两种：

普通生成：每次只出一张。后台调用工作流前，必须判断 ComfyUI 的队列完全为空（没有任何 running / queued 任务）才能执行；队列里有任务就必须等所有任务结束。

队列生成：只在同一个画框里接着加，每次仍只出一张。同一个画框 = 同一个随机种子生成的结果，相同随机种子的结果显示在同一画框中。

队列生成的准入判定（按当前能力判，不看别的画框）：

| 情况 | | ComfyUI 队列现状 | | 当前能力的「加入队列生成」 |

| 1 | | 队列里没有任务 | | 可执行 |

| 2 | | 有「普通任务」正在执行 | | 不可执行 |

| 3 | | 队列里全是当前能力（如图片生成）的队列任务 | | 可执行 |

| 4 | | 队列里全是别的能力（如视频生成）的队列任务 | | 当前能力不可执行；那个别的能力可执行 |

第四种拦截：队列已满。上限由配置决定（maxQueue，具体取值由开发定，1.01 不把某个数字当成需求硬指标），满了不能加，提示「已经排了 N 个，等前面出来几个再加」。共四种拦截情况。

展示与判定分开：右栏是全量执行视图，跨卡、跨能力都显示（这是「让我知道执行了哪个」的需求）；而「能不能加队列」只按当前能力判。两件事不矛盾，不要因为展示跨卡就把守卫也改成全局。右栏顶部状态行要写清「正在跑：能力 · 档位 · 进度，后面还有 N 个」——这一个条件直接决定用户能不能点发送。

0.4 种子机制：ComfyUI 生成，不是本应用生成

硬口径：随机种子是 ComfyUI 执行工作流时生成的，不是本应用生成的。本应用不生成种子、不预设种子、提交时也不知道这一张最终会用哪个种子。

ComfyUI 的实际机制（写事实，不核定实现）：

种子是 KSampler 类节点的输入 seed；配套的 control_after_generate 决定执行后怎么变（fixed / increment / decrement / randomize）。

当它是 randomize 时，具体种子在 ComfyUI 从队列取出这条任务、交给执行引擎那一刻才落定；应用提交工作流时拿不到。

而且 control_after_generate 是执行完才改值，界面上那个数字是「下一次要用的」，不是刚出的这张用的。

seed = -1 是「每次随机」的约定。

因此本应用只能事后回读真实种子：从 /history/{prompt_id}，或成品 PNG 内嵌的 workflow 元数据。卡底显示的种子必须是这个回读值，不是提交时的猜测值。

「同批沿用同一种子」的落地参考（实现方案，非需求硬口径）：首批成品出来后回读到真实种子，后续这一批的队列任务沿用这个值，而不是靠「应用先生成一个再传下去」。需求只要求「相同随机种子的结果显示在同一画框中」，具体怎么让同一批共用同一个种子由开发决定。

输入区没有种子输入框，也不提供「粘贴种子复现」的入口；【复制种子】是把回读到的真实值复制到剪贴板，供记录与复现使用。

0.5 档位、母版与默认档

每个能力对应一个或多个工作流母版；档位 = 某一个工作流母版的不同参数设置；默认档就是母版工作流本身（只读、删不掉）；每个档位都等同一份工作流。

档位不是按资源从低到高排序：档位之间不完全是资源意义上的高低，有些场合档位是不同功能间的切换。所以不存在「降一档」「最费资源那档」，失败重试不改参数。

默认档就是母版，不是另挑一档：用户不选档位时用的就是母版工作流本身（只读、删不掉）。不存在「从档位里挑最常用的一档当默认」这回事，也不需要为它单设字段；「按资源排序取中间」同样不对。

比例是档位里的一组 width / height 成对值，不是输入区控件；张数由生成方式决定（普通生成一次一张、队列生成一次一张），也不需要控件。

已确认口径：默认档就是母版，两者是同一件事。本节只写需求定义，不核定代码实现。

0.6 输入区与参考方式

1.01 的「图片生成」用多个工作流母版（已确认）：这一个能力下不止一个母版。按有没有参考素材选母版：没有参考就走文生图母版，有参考就走参考生图母版（模板）；不需要用户手选，档位挂在各自的母版下。开发原型档位表里的 4 个工作流 tab 就是这组母版，照原型保留：文生图.sdxl、图生图.sdxl、风格参考.ipadapter、文生图.sdxl.turbo；其中 文生图.sdxl.turbo 明确保留——图片生成能力本来就要用到多个工作流母版。

共通部分只有描述区 + 档位（再加按能力决定的参考区、发送键）。按能力定制的只有「参考方式」：有的要图片参考、有的要视频参考、有的要音频参考、有的都要、有的还要控制个数。每个能力声明「收哪几种素材、各几个」，数量上限来自这个声明，不写死 3。

视角、格数、时长、首帧 / 尾帧这类属于档位参数，不是输入区控件。定制化不是给用户的配置项，而是开发侧「一个版本接一个能力」的节奏：1.01 只做图片生成并调通，1.02 再加视频生成。

1.01 输入区没有：比例、张数、种子、步数、CFG、采样器、更多参数。

0.8 原型的定位与参考边界

分工：界面形态与交互结构以原型为主——ComfyBridge-开发原型-1.01.html 的管理台四页、档位表、创作台布局与交互照它做，这是已核对确认过、不重新设计的部分，本文件不覆盖它。功能口径以本文件为准——状态与判定、种子机制、队列规则、档位与母版定义、输入区边界、版本范围按本文件落实。

开发原型是从演示原型复制的「只做减法」副本：只开图片生成、管理台逐字保留。它继承的演示文案、mock 逻辑与旧字段是演示形态，照原型保留即可，不是缺陷、不用改，也不要当成产品行为照抄。界面照原型做，功能按本文件实现。

0.9 其余直接落进正文的口径

访问口令：不需要。删服务设置里的「访问口令」字段、删「开了外网必须设口令 / 强制校验」整段、删「输入口令」这一屏；局域网自由访问，不设登录页、不做身份校验。安全靠「只在一台电脑上跑、不往公网暴露」。

手机适配：手机和 PC 是同一个页面，功能一样，只做布局样式适配屏幕大小（已确认口径）。硬要求只有一条：右栏「执行队列」在手机上不能消失，它是唯一的进度来源。下列是布局建议、不是需求硬规格，具体呈现以原型形态与开发实现为准：能力栏收成顶部下拉 / 抽屉、右栏收成底部浮层或状态条、输入区吸底且键盘弹起不遮挡描述框、历史网格 4 列 → 2 列、触摸目标 ≥ 44px。

任务记录：不做界面查询页，保证记录字段齐即可——时间、能力、档位、工作流、prompt_id、结果、耗时、落盘路径。

成品记录：存能力 id 快照（id + 名字）；删掉能力不删成品，历史里标「能力已删除」。

open-folder：本机工具该做一个仅本机、仅成果目录白名单内的打开目录接口；复制路径作后备。

成品界面文案要求（针对真实成品界面；演示原型是给需求方看的，不受此约束）：① 生成中卡底「第一次生成只会出一张…」② 自检页「用不着在这儿预检」③「演示版不做真下载 / 不做真打包」④ 左栏「灰色 = 还没配好」换成「未配置（下个版本开放）」状态标签 ⑤ 卡头 job_xxxx 内部编号。都不解释设计、不露内部信息。

X56 适用范围：X56「插图里的每句话都要能在真界面上原样找到」约束的是交付给开发的这版文档，不约束探索期演示原型。

| 如果…… |

| 越界（这是 ComfyUI 的地盘） |

3.2 成果物为什么要归档（这是明确要求）

ComfyUI 默认把所有结果都吐在 output/ 根目录里，用久了就是一片乱麻：图片、视频、音频混在一起，文件名还是 ComfyUI_00012_.png 这种流水号，根本看不出哪张是哪个功能生成的。

所以要归档。规则如下：

| 项 |
| 规定 |

| 默认位置 |
| ComfyUI 的 output 目录 / ComfyBridgeOutput / |

| 可改 |
| 管理页可以指定成别的目录（比如换一块大盘） |

| 再按能力分 |
| 每个能力一个子目录，名字就用能力名，比如 图片生成/、9 宫格故事板/、视频生成/ |

| 最终样子 |
| output/ComfyBridgeOutput/图片生成/xxx.png |

| 谁动手 |
| 应用在后端移动文件，用户无感 |

| 动哪些文件 |
| 只动本次生成产生的那几个，别的一概不碰 |

为什么这条不算"越界"：越界的定义是"插手 ComfyUI 自己的事"。output 里的成品是给用户看的产出物，把它们收拾整齐是这个应用的本职。但边界依然存在：只在成果目录里动，成果目录以外一个字节都不碰。

[SVG 图形]

1.4 档位到底"存"在哪：一档 = 一份工作流拷贝

这是全篇最容易做错的一处，所以单独讲一遍。

先说结论：

默认档 = 你从 ComfyUI 导出的那个原始工作流，一格不改，只读、只调用、删不掉。
用户想要的每一档 = 把原始工作流复制一份，把这一档要改的几个参数写进这份复制件的对应节点。
这份复制件就是这一档要调的工作流。

这样做的直接好处：档位不需要一张"值表"，每一档本来就是一份完整、能直接发给 ComfyUI 的工作流。

[SVG 图形]

3.2 两种提交：普通生成 与 队列生成

同一个"提交"动作，在这个应用里被分成了两条路。分不分，决定了用户等 6 秒还是等 40 分钟。

[SVG 图形]

两条路的分工，一句话就能说清：

| |
| 普通生成 |
| 队列生成 |

| 用户的期待 |
| 马上看到，好不好再调 |
| 反正要跑很久，一次性丢过去 |

| 所以 |
| 绝不能排队，忙了就直说 |
| 必须能堆，堆完一个接一个跑 |

| 谁在等 |
| 用户本人盯着屏幕 |
| 用户可以关掉去看别的，回来看结果 |

还有一个前提：同一批只用一个种子。

队列生成不是"再画一张"，而是"把这张画得更细"。种子必须沿用——种子一换，出来的就是另一张构图，用户挑中的那张就没了。所以成品块上写的是尺寸（1024×1024 / 1344×768），而不是每格一个种子：种子整批一样，逐格写反而看不出差别。

这两条要是搞反了（普通生成也进队列、队列只许一个），这个功能就白做了：前者让"快速出图"变成"排队等图"，后者让"批量跑高清"变成"守着一张一张点"。

6.0 外部接入只有一种：斜线技能

本项目对外只提供一种调用方式——在支持斜线技能的 AI 客户端里输入 /，从下拉窗选中对应技能，然后用自然语言描述需求。

没有第二种方式。以下这些明确不做：

| 不做的事 |
| 说明 |

| 不做 MCP 服务 |
| 无论 MCP 多方便，本项目不实现 MCP 端点 |

| 不鼓励外部程序直接调 HTTP 接口 |
| 内部接口存在是因为技能要用它，但不当作对外接入方式宣传，也不提供对接文档 |

| 同上，一律不在范围内 |

为什么要写死这一条：方式一多，就要多维护一套文档、多测一遍兼容性，还容易让人以为"随便什么程序都能接"。只有一种方式，边界最清楚。

6.1 AI 只需要 3 类请求

| 请求 |
| 它问什么 |
| 它得到什么 |

| 看菜单 |
| "你都会做什么？" |
| 一页清单：能力名 + 这个能力有哪几档 + 大概多久 |

| 下单 |
| "按这个要求做一张" |
| 一个任务编号 + "过多久来问一次" |

| 取货 |
| "刚才那单好了吗？" |
| 进度 / 成品地址（已归档到成果目录）/ 失败原因 |

为什么这就够快：AI 不问"你的工作流长什么样"、不问"你装了哪些模型"、不读任何文件、不写任何脚本。它只做三件事，剩下的全在本地进程的内存里完成。

第 03 章功能规格

一、创作台（日常使用的那一页）

1.1 页面布局

[SVG 图形]

布局硬性要求（踩过坑，写进规格）

这页不能用"固定高度 + 内部各自滚动"的做法。那种做法在有些嵌入环境（如预览面板、iframe、某些客户端的 WebView）里会出现滚轮失效、也没有滚动条的假死现象，用户以为页面卡住了。

正确做法是整页滚动：

| 元素 |
| 规则 |

| 页面本身 |
| 可以滚动，内容长了就出滚动条，滚轮始终有效 |

| 顶栏 |
| 顶部吸附，滚动时不消失 |

| 左侧能力栏 / 右侧任务栏 |
| 各自吸附在顶栏下方；内容超长时栏内可滚，不影响整页 |

| 中间对话区 |
| 跟整页一起滚，不做内部滚动容器 |

| 底部输入区 |
| 吸附在窗口底部，滚到哪儿都在，随时能输入 |

一句话判断标准：在任何窗口高度下，滚轮都要能滚，并且一定能看到滚动条。

手机 / 窄屏适配（1.01 必做）

手机和 PC 访问的是同一个页面，功能完全一样，只有布局按屏幕尺寸适配；不做独立移动端页面、不裁剪功能。断点按 390px 重排：

能力栏收成顶部下拉或抽屉（224px 在 390px 屏上占 57%，不能硬撑）。

右栏「执行队列」不能消失——它是手机上唯一的进度来源，收成底部浮层或一条状态条。

输入区吸底；键盘弹起不能把描述框顶没。

历史网格 4 列 → 2 列，触摸目标 ≥ 44px。

前提是布局用 flex / grid，不写死像素。工作量是「补一套媒体查询」，不是做第二套页面。

| 10 |
| 拖入图片 |

| 11 |
| 参考图超过上限 |

| 12 |
| 切换能力 |

| 13 |
| 默认档位 |

| 14 |
| 空描述 |
| 若能力要求必填描述且为空，或必填素材未传，发送按钮置灰 + 一行浅灰说明（两处同一套处理） |

| 15 |
| 多轮微调 |

| 16 |
| 长任务 |

| 17 |

1.4 输入区长什么样（以图片生成为例）

共通部分只有：参考图（按能力决定要不要、要几个）、一排档位、一个描述框、一个发送键。没有比例、没有张数、没有步数、没有 CFG、没有种子、没有采样器、没有「更多参数」。比例是档位里的一组成对宽高值，张数由生成方式决定，都不是输入区控件。

[SVG 图形]

三条规则

技术参数一律不给用户看。 具体是哪几个参数、叫什么，全部藏在工作流和档位里，界面上只出现档位名。

要调就调"档"，不是调"参数"。 一个档 = 一次把好几格一起改掉。勾进来的那几格同时变，由一个动作完成。

档位是"这个工作流自己声明的"，不是全项目统一的。 图片可能是「快速 / 均衡 / 精细」，视频可能是「草稿 / 成片」，音乐是「短一点的 / 标准 / 完整一段」，语音可能干脆没有档位。
具体有几列、每列是什么，由工作流里实际存在的格子决定（见 02 章 §1.4），程序里不预设任何一列。

1.5 每个能力的入口控件，按能力单独定

所有能力共通的只有「描述区 + 档位」。真正按能力定制的是「参考方式」：有的要图片参考、有的要视频参考、有的要音频参考、有的都要、有的还要控制个数。每个能力声明「收哪几种素材、各几个」，上限来自这个声明。这不是给用户的配置项，而是开发侧一个版本接一个能力的节奏：1.01 只做图片生成并调通，1.02 再加视频生成。视角、格数、时长这类属于档位参数，不是输入区控件。

| 能力 |
| 参考方式（按能力声明） |
| 开放版本 |

| 图片生成 |
| 图片参考，数量按能力声明 |
| 1.01 |

| 视频生成 |
| 视频 / 图片参考（按能力声明） |
| 1.02 |

| 音频 / 语音类 |
| 音频参考（按能力声明） |
| 之后版本 |

| 其余能力 |
| 按各自声明追加，创作台骨架不变 |
| 对应版本解锁 |

最后一列只是"通常这么勾"，不是规定。同一个能力换了工作流（比如挂上加速 LoRA），可勾的节点就变了——重新勾一遍即可，程序不动。

每加一个能力，只声明它要哪几种参考素材、各几个；创作台骨架不变。共通的描述区与档位不重复设计。

判断一个控件该不该出现在界面上的标准，问三句话：

不懂 ComfyUI 的人，看到这个词知道该怎么选吗？（不知道 → 不给）

这个值改了，用户能从结果里直观看出区别吗？（看不出 → 不给）

这个值需要和别的值一起改才有意义吗？（是 → 打成一个档，别拆开）

1.6 结果卡长什么样：一次出一张，队列往后接

一张卡 = 一次提交。 卡里可以有不止一个成品：第 1 个是普通生成出来的，后面几个是点【加入队列生成】一张一张接上去的。

[SVG 图形]

五条规则

| # |
| 规则 |

| 1 |
| 卡里第 1 个成品永远来自普通生成；后面的成品只可能来自【加入队列生成】。不允许"一次普通生成出好几张"这种多入口 |

| 2 |
| 一批只有一个种子。它由 ComfyUI 执行工作流时生成（randomize 时执行那一刻才落值），本应用不生成、不预设、提交时拿不到；真实值从 /history/{prompt_id} 或成品内嵌 workflow 元数据回读。之后这一批里所有队列任务都用这个固定值。成品 2、成品 3 跟成品 1 是同一张构图，只是换了档 |

| 3 |
| 队列还没出片时，卡里就占一个虚线占位块，写着"成品 3 · 排队中，前面还有 N 个"。用户在点完的一瞬间就知道自己排到了第几，不用去别处查 |

| 4 |
| 占位块从"排队中"变"正在采样 60%"再变图，全程在同一张卡里，不新开卡、不跳位置 |

| 5 |
| 卡底只留一行：种子 + 【加入队列生成】【↻ 再来一张】。不写"共 N 个成品"、不写"档位 精细 / 默认"、不贴归档路径——这些信息分别在卡头、大图、下载里 |

成品块上写什么：第一行 成品 N，第二行写这一档的尺寸（如 1024×1024 / 1344×768）。因为种子整批一样，写种子反而每格都一样、看不出差别；写尺寸才一眼看出"这格更精细"。

只有跟基准档不同的那几格，左上角才多一个小档位标签（如"精细"）。基准档不加标签，否则每格都挂一个，反而吵。

为什么不给每个成品单独开一张卡？因为用户是按"这句话"记事的，不是按"第几次提交"记事的。同一句话的 4 个版本散在 4 张卡里，翻起来比不生成还累。

1.7 两种生成：普通生成 与 队列生成

这是这一页唯一的"硬规则"，所有会提交任务的地方都要按它判断，包括图片、视频、音乐、语音、故事板。

| |
| 普通生成 |
| 队列生成 |

| 入口 |
| 发送键（↑ 或 Ctrl/⌘+Enter）、卡片的【🔁 再来一张】、失败卡的【重试一次】 |
| 已完成卡片底部的【🕒 加入队列生成】 |

| 什么时候能点 |
| ComfyUI 队列完全为空（没有任何 running / queued 任务）；否则等队列里所有任务结束 |
| 队列为空，或队列里全是当前能力的队列任务 |

| ComfyUI 正忙时 |
| 弹一条提示，说清"谁在跑、跑到几成"，不提交、不进队列 |
| 仅当前能力匹配且队列未满时允许；能力不匹配或队列已满时拦住并说明原因 |

| 出片落在哪 |
| 新开一张卡，里面是成品 1 |
| 加进同一张卡，成品 2、成品 3… |

| 种子 |
| 由 ComfyUI 执行时生成，应用事后回读 |
| 用回读到的固定种子，只换档位 |

| 典型用途 |
| 试描述、试档位，要立刻看到结果 |
| 挑几张满意的，批量跑高清精品 |

为什么普通生成坚决不进队列

普通生成本来就是"快出片"用的。把一次普通生成塞进队列，用户会面对一条十几分钟不动的进度条，还以为坏了——这比直接告诉他"现在忙，等会儿"体验差得多。所以宁可拦住，也不排队。

为什么队列生成必须能连着点

高清精品一张就要跑很久。如果每点一次都得等上一次跑完才能点下一次，那"批量"就没意义了。所以队列是允许堆积的：点一次加一个，全部排在后面，一个跑完自动接下一个，人可以去干别的。

四种会被拦住的情况（都要写清"是谁在跑"）

| 场景 |
| 提示里必须有的信息 |

| 普通生成撞上正在跑的任务 |
| 在跑的是哪个能力、哪一档、到几成了；并说明"这次不提交，也不排队" |

| 加入队列生成撞上没跑完的普通生成 |
| 同上，并说明"队列生成要等普通任务结束才能加" |

| 加入队列生成撞上别的能力的队列任务 |
| 说清队列里跑的是哪个能力；当前能力要等它结束才能加 |

| ComfyUI 没连上 |
| 直接说没连上，先启动 ComfyUI。不要假装提交了 |

| 队列已满（上限见配置 maxQueue，取值由开发定） |
| "已经排了 N 个，等前面出来几个再加" |

队列在页面上出现在三个地方：右栏顶部状态行、右栏的「执行队列 N 个」清单、卡片头部的小标签。右栏是全量执行视图——跨卡、跨能力都显示，顶部要写清「正在跑：能力 · 档位 · 进度，后面还有 N 个」，这是用户判断能不能发的唯一依据；但「能不能加队列」只按当前能力判。展示跨卡、判定按能力，两件事不矛盾。三处都指向同一件事，用户在任何位置都不会以为「点了没反应」。

二、管理台（配置那几页）

四页固定为：能力与工作流 / 档位表 / 服务设置 / 自检。自检只查「连不连得上 + 目录能不能写」两项，不做工作流逐个体检。

管理台永远是左侧菜单 + 右侧表单，一共 4 页。初次使用有引导。

[SVG 图形]

这张图里的每一个字，都是使用者在该页会看到的样子。不给使用者看的东西不进画面：哪个能力挂了几个工作流、工作流叫什么文件名、档位是怎么拷出来的，一律不显示——它们属于配置文件，属于实现，不属于界面。

2.1 页面一：能力与工作流

| 你能做的 |
| 细节 |

| 能力从哪来 |
| 只来自配置文件（config.yaml 里的能力清单）。页面上不提供"新增能力"，更不提供"添加工作流" |

| 工作流从哪来 |
| 配置文件里每个能力下面写 1 个或多个工作流文件名。页面不展示工作流清单、不展示文件名、不展示挂了几个——使用者只需要知道这个能力能不能用、有哪几档 |

| 编辑能力 |
| 界面不提供编辑能力；名字、图标、一句话介绍（会展示给 AI 和用户）、默认档都写在配置文件里、可改 |

| 启用/停用 |
| 停用后从创作台消失，但配置保留；没挂工作流的能力不能启用，创作台灰着显示「未配置」且不可点，下个版本开放时再解锁 |

| 排档位 |
| 只有挂了工作流的能力才能点「配置」。没挂的显示「未配置」，整项不可点，等下个版本解锁；管理台也不提供「添加工作流」入口 |

| 复制能力 |
| 比如"图片生成"复制一份改成"图片生成（写实版）" |

| 删除能力 |
| 二次确认，提示"这不会删除工作流文件" |

常见能力名（照抄到配置文件里即可，不是页面上的模板）：图片生成、参考风格生图、线稿图生成、简单手绘创作、角色设定图、场景设定图、道具设定图、4 格故事板、6 格故事板、9 格故事板、视频生成、参考生成视频、首尾帧生成视频、音乐生成、参考生成音乐、语音生成、声音克隆。

一个能力实际能干什么，取决于配置文件里给它挂了哪个工作流。每个能力的输入区具体长什么样（几个上传位、几档、有没有开关），都要你按 1.5 那张表单独定，没有现成的参数。

2.2 页面二：工作流配置（核心页面）

这个页面只做两件事：① 勾出哪些参数给用户调；② 把用户要的那几档"造"出来（每档 = 一份工作流拷贝）。 工作流文件和出片节点都不用在这里选——启动时从服务自己的工作流目录自动读取。

[SVG 图形]

六个设计要点

| 要点 |
| 做法 |

| 一档 = 一份工作流拷贝 |
| 点【添加】时，系统把原始工作流整份复制到 ./workflows/ComfyBridge/，文件名带档位名（如 文生图.sdxl__快速.json），再把 ④ 里填的值写进这份拷贝的对应节点。这份拷贝就是这一档运行时真正提交的工作流——档位不需要另存一张"值表"。 |

| 默认档 = 原始工作流本身，只读 |
| ⑤ 的第一行永远是「默认」，它就是那个原始文件，一个字节都不改。不能改名、不能删、参数控件全部禁用。用户点「默认」= 原样跑一次。这样任何一次失败都能立刻分清是"工作流本身有问题"还是"某一档配错了"。 |

| ④ 是"造档位"的地方，不是"选档"的地方 |
| ④ 里只有两样东西：勾中的节点参数 + 档位名称输入框 + 【添加】。它和创作台的档位按钮没有任何关联——你在 ④ 里填的是"下一个档位长什么样"，填完点添加才会变成一档。 |

| ⑤ 是列表，不是表格；一档一行 |
| 一行 = 档位名 + 改动项数 + 【✎ 编辑】+【✕ 删除】。点【编辑】，这一档那份拷贝的全部参数展开在下面，可以接着改任何一格。默认档那行只有【👁 查看】和一个禁用的 ✕。 |

| 提示词 / 参考素材 / 出片节点不进清单 |
| ② 只列参数节点。提示词由创作台填（服务端按字段名自动认出那个文字格子）；参考图/音频数量不固定，由服务端按用户上传的数量动态插入对应节点；出片节点（SaveImage / SaveVideo / SaveAudio / PreviewImage）由服务端按 class_type 自动认，页面上不选。这三类连复选框都不给，避免有人去填一个没用的值。 |

| 工作流文件不用选、不用改路径 |
| ① 只显示文件名和"自动读取"标签。每个能力用哪个工作流是固定的，文件放在服务自己的工作流目录里（配置里登记一次），启动时自动读、读完节点就摊在 ②。页面上没有"选择文件""重新读取"，也没有可编辑的路径框——想换工作流就改配置文件里那一行的文件名，页面上没有"选文件"这一说。 |

参数用什么控件，看它本来是什么形态

| 参数形态 |
| 控件 |
| 在页面上长什么样 |

| 整数 / 小数 |
| 输入框（数字） |
| 带上下限和步长，旁边标"必须是 16 的整数倍"这类提示 |

| 是 / 否 |
| 开关 |
| 绿点=开、灰点=关，点一下切换，不用打字 |

| 枚举（只能选一个） |
| 选择菜单 |
| 选项来自工作流本身，打字打错就会跑不起来 |

| 枚举（能选好几个） |
| 多选 |
| 勾选框列表，可以同时选 concat 和 average |

| 一段文字 |
| 输入框（文字/多行） |
| 超过一行自动变多行，占满整行 |

每个参数旁边都有一个小标签写明这是哪种控件（如 输入框（数字）、选择菜单、开关），配置时不用猜。

为什么是"勾节点"而不是"勾字段"

你想调的东西，脑子里本来就是"我要改采样器那几步"、"我要改空 latent 的尺寸"。按节点勾，配置时不用在十几个字段名里翻；换工作流也不用重新认一遍字段名——节点名在 ComfyUI 里本来就看得见。

2.3 这个页面怎么用（四步）

[SVG 图形]

为什么管理台没有"分流规则"页：一个能力挂了多个工作流时，用哪个由配置文件里每个工作流的条件决定（见 02 章 2.1）。这些条件和顺序属于部署信息，页面上不给改——想改就改 config.yaml，点「重读配置」。

页面上同样没有"添加工作流"：没在配置里挂上工作流的能力，档位表是只读的一句说明，一个可点的编辑控件都没有。

| 成果目录：生成成功后把结果归到哪里 |
| ComfyUI的output目录/ComfyBridgeOutput |

| 路径 |
| 工作流 json、上传文件、任务记录各放哪 |
| ./workflows、./data/uploads、./data/tasks |

| 存储与清理 |
| 任务记录保留几天、最多留几条、当前占用 |
| 7 天 / 500 条 |

每个设置项旁边都有"为什么"的一句话，不让人瞎猜。

这一页没有"运行"这一块

服务设置只放四块：连接、成果物归档、路径、存储与清理。原来那块"同时跑几个任务 / 最多排多少队 / 默认超时 / 实时预览帧"整块去掉，页面上一个字都不留：

| 不显示 |
| 实际怎么定 |

| 同时跑几个任务 |
| 固定 1 个（ComfyUI 本身一次只能跑一个） |

| 等待超时 |
| 不设（本机内网直连，慢就是真的在算） |

| 实时预览帧 |
| 关（只显示步数和进度条） |

| 排队上限 |
| 写在配置文件里（maxQueue，具体取值由开发定），页面上不显示也不给改 |

这些都是"不会变的部署事实"，摆在页面上只会让人以为需要调。真要改上限，改 config.yaml 再点「重读配置」。

与"谁能排进队列"配套的一条硬规则：只有结果卡上的【加入队列生成】会让任务排到 ComfyUI 后面。发送、再来一张、重试这些普通生成，忙了只提示、不提交、不排队（见 §1.7 与 X36~X41）。

成果目录的详细规则

| 项 |
| 规则 |

| 默认值 |
| <ComfyUI 的 output 目录>/ComfyBridgeOutput |

| 能否改 |
| 能。管理页可以指定成任意有写权限的目录（比如 D:/AI出图/ComfyBridge） |

| 子目录 |
| 系统自动在这里面按能力名建子目录，比如 图片生成/、9 宫格故事板/、视频生成/ |

| 最终路径 |
| <成果目录>/<能力名>/<原文件名> |

| 什么时候移动 |
| 任务判定成功后立刻移动 |

| 移动失败怎么办 |
| 任务仍算成功（图已经生成了），但结果卡片上明确标注"归档失败"并给出原因，不让用户以为文件丢了 |

| 能否关闭归档 |
| 不能。归档是明确要求，不提供"关掉"的开关 |

| 会动哪些文件 |
| 只动本次生成的那几个，见第 07 章 X11、X12 |

界面上的表现：结果卡底部不贴归档路径（以 X43 为准）。路径在大图弹窗里可看、可复制，并有「打开所在目录」一键动作（本机 open-folder 接口，仅成果目录白名单内）；复制路径作后备。

服务设置里不会出现"开启 MCP 入口"这类选项。 本项目对外只有斜线技能一种接入方式，不提供第二种。

任务记录不做界面查询页，保证记录字段齐即可：时间、能力、档位、工作流、prompt_id、结果、耗时、落盘路径。出问题直接看文件，够排障用。

成品记录存能力 id 快照（id + 名字），不只是名字；以后改名 / 删能力，历史里才对得上。删能力不删成品，历史里标「能力已删除」。

归档失败是卡片上的可见状态（黄标 + 原因 + 原路径），成品照常可看可下载；它和「配置被手改坏」是两回事，样式可复用、语义必须分开。

2.5 页面四：自检

这一页只有两条结果，点一下查完，1 秒内出结果：

[SVG 图形]

除了这两项，什么都不检查。 尤其是不逐个检查工作流：

| 不做 |
| 为什么 |

| 不检查某个工作流缺哪个节点 |
| ComfyUI 真跑的时候会直接说"节点 X 的类型 IPAdapter 不存在"，比预检更准，还省得维护一份节点对照表 |

| 不检查档位值合不合法 |

| 不检查显卡、不估显存、不建议降档 |
| 这些是 ComfyUI 和显卡的事，本应用不插手 |

一个工作流配错了，正确的发现方式是在创作台真跑一次：卡片变红、写清哪个节点哪一格、给一个动作按钮。自检不抢这件事。

四、资源占用

| 项 |
| 目标 |
| 说明 |

| 进程数 |
| 1 |
| 页面由后端顺手发出 |

| 内存 |
| ≤ 120MB 常驻 |

六、安全（本机工具的合理尺度）

第 05 章推进步骤

原则：先立骨架，再长肉。 骨架阶段一条生成能力都不要，先把"加能力"这件事变得顺滑；然后从最简单的工作流开始，一个一个往里加。

[SVG 图形]

阶段 1｜骨架（能配、不能生成）

这一步交付什么

| 交付 |
| 说明 |

| 一个能启动的服务 |
| 打开浏览器就能看到创作台（空状态）和管理台 |

| 配置文件读写 |
| 首次启动自动生成一份默认文件；改完保存即生效；只维护一个当前版本 |

| 管理台 · 能力与工作流 |
| 只读列出配置里的能力与工作流；启停、复制、删除、重读配置 |

| 管理台 · 工作流配置 |
| 自动读 json → 勾参数节点 → 填值加档位 → 去创作台试 |

| 配置文件 · 挑工作流的条件 |
| 加条件、调顺序、设兜底（页面不提供这一页） |

| 管理台 · 服务设置 / 自检 |
| 四个页面齐活 |

| 创作台 |
| 能读到配置、渲染出侧边栏和档位按钮；点发送只提示"还没有接通道" |

为什么先做这个：后面每加一个工作流，你都要在这个界面上操作。界面不顺手，后面会加得很难受。

验收标准

全新环境启动，自动生成配置文件，管理台可打开。

新增"图片生成"，把 json 放进工作流目录，系统读出 12 个节点；勾两个节点、加三档（快速/均衡/精细），保存。

创作台侧边栏出现"图片生成"，输入区只有"一个描述框 + 三个档位按钮"，没有任何技术参数。

手工改配置文件（比如改端口），重启后生效；改坏一个字段，能明确报错指出哪一行有问题。

自检页面只有两条：ComfyUI 连得上、成果目录可写；配错的工作流靠真跑一次在卡片上报出来。

阶段 2｜通道（能提交、能盯、能取回）

这一步交付什么

| 交付 |
| 说明 |

| ComfyUI 连接 |
| 检测是否在线（顶栏那个灯）；一条常驻连接接收所有消息 |

| 提交 |
| 把填好的东西发给 ComfyUI，拿到任务编号 |

| 盯进度 |
| 把 ComfyUI 的消息翻译成"第几个节点、第几步、百分比" |

| 取成品 |
| 按自动认出的出片节点，把图片/视频/音频文件取回来 |

| 任务管家 |
| 排队（一次只跑一个）、队列上限、取消、失败分类 |

| 创作台卡片 |
| 生成中卡片（进度条）、完成卡片（成品网格）、失败卡片（原因） |

这一阶段的"第一个工作流"：选你手上最简单、最稳的那个文生图工作流。不要一上来就做视频或克隆。

验收标准

创作台写一句话点发送 → 出图 → 能下载。

同时发 3 个：第一个跑，后两个排队，逐一完成。

ComfyUI 没启动时点发送：明确提示"请先启动 ComfyUI"，不是转圈或报一堆错。

生成中点取消：ComfyUI 里那个任务真的停了。

生成中把服务重启：重启后任务还能接着显示结果（不丢）。

第 06 章加一个工作流的清单

这张清单可以打印出来贴显示器旁。每加一个工作流，从上往下走一遍，10 分钟内能完成。
全章的核心只有三句：先勾节点（哪几个参数节点给人调）；再填值加档（点添加 = 复制一份工作流）；默认档永远是原始工作流，碰都不碰。 节点是从工作流里读出来的，不是固定的。

一、五步流程图

[SVG 图形]

二、第 3 步：先勾节点，再加档位

这一步分两小步，顺序不能反。 先决定"这个工作流里哪几个参数节点该给人调"，再决定"加几档、每档填什么"。

2.1 第一小步：勾节点

读进工作流后，页面左下会把参数节点列出来（编号 + 类型 + 它自己带的参数）。可以多选。

勾中一个节点 = 它身上的全部参数进入设置区。勾了 KSampler，就是种子/步数/CFG/采样器/调度器/改写幅度一起进来，不用一格格挑。

勾哪几个？ 想两件事：

| 问自己 |
| 勾还是不勾 |

| 这个节点上的东西，改了用户能看出区别吗？ |
| 看不出 → 不勾（比如 Checkpoint 加载、VAE 解码、文件名前缀） |

| 这些值必须一起改才有意义吗？（比如宽和高） |
| 是 → 勾它，因为它天然打包在同一档里 |

勾几个？ 1~3 个节点最舒服。一个都不勾也完全合法——那就是"这个工作流只跑默认档"，最朴素的语音合成常常如此。

2.2 常见的勾法（只是经验，不是规定）

| 工作流长什么样 |
| 通常勾哪几个节点 |
| 就会出现哪些参数 |
| 为什么 |

| 普通文生图 |
| 尺寸节点（EmptyLatentImage）+ 采样器（KSampler） |
| 宽 / 高 / 张数 / 步数 / CFG / 采样器 / 调度器 |
| 一起变才有"快速/精细"的区别 |

| 图生图 / 重绘 |
| 缩放节点（ImageScale）+ 采样器 |
| 宽 / 高 / 改写幅度 / 步数 / CFG |
| 改写幅度是这类能力的命门 |

| 参考图（IPAdapter 之类） |
| 尺寸 + IPAdapter 节点 + 采样器 |
| 宽 / 高 / 参考强度 / 参考方式 / 步数 |
| 强度和方式决定"像不像参考图"；参考方式还是个下拉 |

| 绑了加速 LoRA（LCM / Turbo 等） |
| 采样器 + LoRA 节点（宽高常常不用动，不勾） |
| 步数 / CFG / LoRA 强度 |
| 加速模型只吃 4~8 步、CFG 1~2；40 步反而是有害配置 |

| 视频（有 length / fps） |
| 视频节点 + 采样器 |
| 宽 / 高 / 帧数 / 步数 / CFG |
| 帧数直接决定时长和显存 |

| 音乐（MusicGen 这类） |
| 音乐采样节点 + 音乐加载节点 |
| 时长 / 速度 / 输出设备 / 风格（下拉） |
| 没有宽高、没有步数，硬塞就是废列 |

| 语音 / 声音克隆 |
| 加载节点 + TTS 节点 |
| 音色（下拉）/ 语速 |
| 这类给的是"音色"，不是画质档 |

| 参考生成视频（多图 + 多音频） |
| 视频节点（H3 这类） |
| 时长 / 分辨率（下拉）/ 动作幅度 / 音画同步（开关） |
| 这是唯一会出现开关的典型场景 |

注意"加速 LoRA"这一行：同一个能力换成一个绑了加速 LoRA 的工作流之后，该勾的节点本身就会变——原来勾「尺寸 + 采样器」，这时只要「采样器 + LoRA」。
这正是为什么不能写死——节点是跟着工作流走的，工作流一变就回左边重勾一遍。 演示原型里「图片生成」下面就有这么一个工作流（文生图.sdxl.turbo），可以直接点开看差别。

2.3 第二小步：加档位

勾完节点，④「新增档位」里会出现每个节点一块参数，每个参数按它自己的类型摆控件：

| 参数类型 |
| 长什么样 |
| 例子 |

| 数字 |
| 输入框，能上下调，旁边标范围和步长 |
| 步数 28、CFG 7.0、帧数 81 |

| 是 / 否 |
| 开关（绿=开，灰=关） |
| 音画同步 |

| 枚举单选 |
| 下拉菜单，选项来自工作流本身 |
| 采样器 dpmpp_2m、分辨率 720p、音色 |

| 枚举多选 |
| 勾选框列表 |
| IPAdapter 的组合方式 |

| 文字 |
| 文字输入框（长的会自动变多行） |
| 文件名前缀、画风描述 |

在 ④ 里填好一组值、在下面写上档位名、点【＋ 添加】：

系统把原始工作流整份复制一份到 ./workflows/ComfyBridge/，文件名带档位名（如 文生图.sdxl__快速.json），再把 ④ 里填的值写进这份拷贝的对应节点。
这份拷贝就是这一档运行时真正提交的工作流。

⑤ 里是已有档位的列表，一行一档：

| 档位名 |

2.4 哪些节点根本不会出现在清单里

这三类节点改了没意义，所以连复选框都不给：

| 节点类型 |
| 典型节点 |
| 为什么不让设 |
| 谁负责 |

| 提示词 |
| CLIPTextEncode / MusicGenTextEncode / 各类 text encode |
| 内容是用户在创作台现打的，不是配置项；每档写死一句提示词没有意义 |
| 创作台大输入框；⑥ 只绑"绑到哪一格" |

| 上传参考 |
| LoadImage / LoadAudio / LoadVideo |
| 用户传几张就有几个，数量不固定，要由服务端按数量动态插入并连线 |
| 创作台的上传按钮 + 服务端动态拼 |

| 出片 |
| SaveImage / SaveVideo / SaveAudio / PreviewImage |
| 只负责把结果拿出来，没有"选哪个值"这回事 |
| 按 class_type 自动认，配置页不列、不选 |

剩下的才是参数节点。没勾的参数节点不会消失——它照样在工作流里跑，值用 json 里的原值，用户在创作台永远看不到。

| 参数 |
| 勾不勾 |
| 为什么 |

| Checkpoint 加载（模型文件名） |
| 不勾 |
| 换模型 = 换工作流，不该给用户挑 |

| LoRA 名字 |
| 不勾这一格，勾节点也行 |
| 名字给用户看没意义；名字这格在下拉里改一下就行，但通常不用动 |

| 采样器 / 调度器 |
| 勾进来没关系 |
| 它们在档位里变成下拉菜单，用户看不懂就不看 |

| 种子 |
| 勾不勾都行 |
| 一般留随机；要复现就在结果卡上点"复制种子" |

| 文件名前缀 |
| 不勾 |
| 归档时应用自己接管 |

| VAE 解码、预览节点 |
| 不勾（没有可调的值，也不会出现在清单） |
| — |

| 张数 / 批次 |
| 不勾 |
| 一次出几张由工作流定，不做成用户选项 |

2.5 描述框绑到哪

一个工作流只有一个描述框。这个格子不用你在页面上选——读工作流时就自动认出来了，认的规则是"排除掉别的东西之后，唯一那个文字格子"：

| 工作流 |
| 自动认到的格子 |

| 文生图 |
| 正向 CLIPTextEncode 的 text |

| 故事板 |
| StoryboardGrid 的 cells |

| 视频 |
| 提示词节点的 prompt |

| 音乐 |
| 音乐编码节点的 prompt 或 genre |

（负向提示词的 CLIPTextEncode 会被排除；一个工作流里要是有两个正向文字格子、认不准，服务会按节点编号取第一个，建议你在 ComfyUI 里合并成一个再导出。）

负向提示词不放描述框（用户写不好负面词）。它就在工作流自己的那个负面词格子里，跟别的参数一样进档位，每档可以不一样。

2.6 换工作流 / 改工作流之后怎么做

这是最容易出事的场景，单独列出来。

| 情况 |
| 会发生什么 |
| 怎么办 |

| 把工作流文件换成新版（节点名变了） |
| 老节点在新清单里已经没有了，勾自然失效 |
| 回左边 ② 按新清单重新勾；旧档位只剩默认档，重新加 |

| 在原来基础上加了一个 LoRA 节点 |
| 节点清单里多了一行 LoraLoader |
| 在 ② 里勾上它，④ 里就多出 LoRA 强度那一格，加档时填上 |

| 想少给用户一个参数 |
| 取消勾这个节点 |
| 它的参数立刻从 ④⑤ 消失，各档拷贝里对应的值一起清掉 |

| 只想设节点里的一格（比如只要步数，不要种子） |
| 做不到，也不建议做 |
| 一个节点是成套的。真要拆，就在 ComfyUI 里把想分开的参数拆到两个节点，再重新导出 |

| 某一个档想推倒重来 |
| 删掉这一档，重新在 ④ 填一次 |
| 默认档不受影响，因为它从来没被改过 |

| 完全不想要档位了（比如改成语音） |
| 一个节点都不勾 |
| ④ 显示空态，⑤ 只剩默认档，创作台只有一个默认按钮 |

不需要改程序，也不应该改程序。 如果某次换工作流时你发现"非改代码不可"，说明读工作流的逻辑有问题，回去修那个，别改档位的结构。

三、常见故障速查

| 现象 |
| 原因 |
| 怎么办 |

| 管理台左边节点是空的 |
| 导出成普通格式了，或配置里文件名写错 |
| 在 ComfyUI 用"保存(API格式)"重新导；核对 config.yaml 里的文件名 |

| 节点数量比界面里少 |
| 正常：API 格式只导出"执行用得到的" |
| 不用管 |

| 试跑报"节点 XX 不存在" |
| ComfyUI 没装那个自定义节点 |
| 装节点包，重启 ComfyUI，再试跑 |

| 试跑报"值不在列表里"（模型名） |
| 固定值里的模型文件名和实际不一致 |
| 在 ComfyUI 里换模型重新导出，或改固定值 |

| 跑通了但页面没出图 |
| 工作流里没有 SaveImage / SaveVideo / SaveAudio 这类出片节点 |
| 在 ComfyUI 里加一个保存节点再重新导出 |

| 出图了但是一堆噪点 |
| 某一档的步数填太低（比如 3） |
| 打开档位表，把那一档的步数调到 10 以上 |

| 某一档报"维度错误 / 尺寸不对" |
| 宽或高不是 16 的整数倍 |
| 改成 16 的倍数（1024、1280×704、1536 都行） |

| 快速档和精细档出来的图一模一样 |
| 两档填了同样的值 |
| 改数值，别只改名字 |

| 换工作流后，原来勾的节点不见了 |
| 新工作流里没有这个节点 |
| 回左边 ② 重新勾；清单是按新文件重新读的 |

| 勾了某个节点，但创作台上完全看不出差别 |
| 这个节点上的东西改了对结果没影响（或者被别的节点覆盖了） |
| 取消勾它。勾进档位的标准是"用户能感知" |

| 节点列表里有的节点勾不上（灰的） |
| 它只有连线，没有可改的参数 |
| 正常。连线改不了；要改就得改工作流本身 |

| 加了加速 LoRA 后出图糊 / 过曝 |
| 还在用原来的步数和 CFG |
| 按加速模型的推荐值重排档位（通常步数很低、CFG 接近 1），或直接只勾"步数 + LoRA 强度" |

| 生成中一直 0% |
| 有些工作流的节点不汇报进度 |
| 正常现象，等它跑完；视频类常见 |

| 上传了参考图但生成的图跟图无关 |
| 参考图没接进正确节点 |
| 检查这个工作流的参考图节点是不是 LoadImage |

| 任务成功但找不到文件 |
| 归档失败了 |
| 结果卡上会显示原路径；检查成果目录是否可写 |

5.1 档位拷贝放哪儿

点【添加】生成的拷贝统一放在一个独立子目录，默认 ./workflows/ComfyBridge/（可在"服务设置 → 拷贝目录"改）：

| 文件 |
| 是什么 |
| 谁能改 |

| 图片生成-文生图-sdxl.json |
| 你导出的原始工作流 |
| 只有你（重新导出覆盖） |

| ComfyBridge/文生图.sdxl__快速.json |
| 「快速」档的拷贝 |
| 只有这个应用（按 ④ 里填的值自动写） |

| ComfyBridge/文生图.sdxl__精细.json |
| 「精细」档的拷贝 |
| 同上 |

三条纪律：

拷贝目录整个是应用自己的地盘，不要手工编辑，下次保存会被覆盖。

原始工作流永远不被写。想改原始值，回 ComfyUI 重做、重新导出。

换工作流时，旧拷贝已经对不上新节点，保存时会被提示"有 N 个档位要重建"，选重建即可。

第 07 章禁止事项（写死，不要自行发挥）

这一章是给后来接手的人或 AI 看的。如果你没有参与过前面的讨论，只拿到这份文档，请把这一章当成硬约束：下面每一条都是明确决定过的"不做"，不是"还没决定"。

看到"可以优化一下"的冲动时，先回来对照这一章。

一、接入方式：只允许斜线技能

| 编号 |
| 禁止 |
| 说明 |

| X1 |
| 禁止实现 MCP 服务 |
| 无论 MCP 多流行、多方便，本项目不提供 MCP 端点，也不做 MCP 相关的配置项 |

| X2 |
| 禁止把 HTTP 接口当对外接入方式 |
| 内部接口存在只是因为斜线技能要用；不写对外对接文档、不做 API 使用示例、不在界面上宣传 |

| X3 |
| 禁止做 OpenAI 兼容接口 / 命令行工具 / 浏览器插件 |
| 一律不在范围内 |

唯一合法的使用姿势：在支持斜线技能的 AI 客户端里输入 /，从下拉窗选中技能，然后用自然语言描述需求。

二、界面：技术参数不对最终用户暴露

界面上的每一句话都是写给"用它的人"，不是写给做它的人。 这条比下面任何一条都容易违反，所以单列一节（§二之后 2.4）。凡是解释"为什么这么设计""我们刻意不做什么""这是部署信息"的句子，一律搬到需求文档里，界面上一个字都不留。

| 编号 |
| 禁止 |
| 原因 |

| X4 |
| 禁止在创作台上出现步数、CFG、采样器、种子、Checkpoint 文件名、VAE 名等技术参数 |
| 用户看到也不知道怎么选；想调这些的人会直接去用 ComfyUI。管理台的配置区里可以有——那是给配置的人看的 |

| X5 |
| 禁止让用户逐个字段打钩凑列（"宽勾一下、高勾一下、步数勾一下"那套） |
| 配置成本高、容易漏勾（勾了宽忘了高就出半吊子状态）。勾的单位是节点：勾一个节点，它的参数成套进来 |

| X6 |
| 禁止设计"全项目统一的一套档位" |
| 每个工作流（不是每个能力——一个能力可以挂好几个工作流）的档位都必须单独定。图片和视频的档完全不同，套统一的必然有一半是废话 |

| X7 |
| 禁止在创作台上出现"参数映射""节点 ID""字段名"这类内部词汇 |
| 用户不需要知道系统内部怎么对应。管理台里字段名可以显示（用小字灰字），因为配置的人需要核对 |

| X7b |
| 禁止在档位之外再给用户留"单独改某一个值"的口子（例如"高级设置""微调步数"） |
| 那就退化成逐个调参数了。要调就把那一档整份拷贝改掉 |

| X21 |
| 禁止把"宽 / 高 / 步数 / CFG"写死成固定几列或固定字段 |
| 这四个只是文生图常见的组合。音乐工作流没有宽高，绑了加速 LoRA 的工作流只该有步数和 CFG，语音只有音色和语速。写死等于给一半能力配了一堆废参数 |

| X22 |
| 禁止在程序里按字段名做特殊判断（例如"如果字段叫 steps 就显示成 X 步""如果叫 width 就自动配 height"） |
| 一旦按名字分支，就等于把字段名写死了。字段名要能随便换、随便加，程序只认"有个字段、它是什么类型、有个值" |

| X23 |
| 禁止给所有能力预置同一套节点/字段模板（"图片模板 / 视频模板 / 音乐模板"这种） |
| 模板看着省事，但工作流一换就全错，还得手动改回来，等于多一层壳。节点只能从当前这个工作流里读出来再勾 |

| X26 |
| 禁止把档位做成表格（一档一行，列是参数） |
| 档位是列表：一行一档，只有名字 + 改动项数 +【编辑】+【删除】；点编辑才展开这一档那份拷贝的全部参数。做成表格，参数一多就横向撑爆 |

| X27 |
| 禁止让"默认档"可改、可删、可改名 |
| 默认档就是原始工作流本身，只读。它存在的意义是给排查一个基准：默认档跑通了 → 问题在某一档的值上；默认档也跑不通 → 问题在工作流本身。一旦允许改它，这个基准就没了 |

| X24 |
| 禁止因为"一个节点都没勾"就报错或拦住用户 |
| 语音合成这类工作流本来就可能只该有默认档。没勾 = 只有默认档，这是正常状态，不是配置错误。④ 显示空态、④ 的【添加】置灰就够了 |

2.1 参数控件：形态必须跟着类型走

| 编号 |
| 禁止 |
| 原因 |

| X29 |
| 禁止把所有参数一律渲染成文本框 |
| 采样器、调度器、音色、分辨率都是枚举，给文本框等于逼用户背字符串，打错一个字母就整个任务失败。枚举必须给下拉或单选 |

| X30 |
| 禁止把"是/否"参数渲染成文本框（让人填 true/false 或 1/0） |
| 必须给开关。用户看到 true 只会问"这要填啥" |

| X31 |
| 禁止把多选参数渲染成下拉（下拉天然只能选一个） |
| 数组类型的参数必须给多选勾选框，否则会把多值参数错误地降成单值 |

| X32 |
| 禁止由我们"规定"某个字段该用什么控件（比如硬写"width 用数字框、某某字段用下拉"） |
| 控件形态要读参数自己声明的类型（整数/小数/布尔/枚举及选项/数组/字符串）。表里没有的新字段按字符串处理即可，不要报错 |

| X33 |
| 禁止在配置页上隐藏参数类型 |
| 每个参数旁边都要标出"这是哪种控件"。不标，配置的人会怀疑"这个我该填数字还是文字"，于是去翻工作流 json |

2.2 哪些节点不该出现在可设置清单里

| 编号 |
| 禁止 |
| 原因 |

| X28 |
| 禁止把提示词节点、上传参考节点、出片节点放进"可设置"清单（连复选框都不给） |
| 改它们没有意义：提示词是用户在创作台现打的，每档写死一句没意义；参考图/音频数量不固定，要由服务端按用户上传的数量动态插入；出片节点只负责把结果拿出来。让它们出现在清单里，只会诱导人去填一个没用的值 |

| X28b |
| 禁止在前端管理页暴露"参考素材有几个"这种设置 |
| 数量由用户这次上传了几个决定，是运行时的事。管理页只需要选一个"这类素材绑到哪个节点"，剩下由服务端动态拼 |

| X28c |
| 禁止把"识别哪些节点是提示词/上传/出片"做成字段名清单（例如判断字段叫 text 就是提示词） |
| 要按节点类型（class_type）判断，不是按字段名。别人家的提示词节点可能叫 prompt、t5xxl、*_text_encode，按字段名判断必然漏 |

2.3 提交与排队：两条路，不许混

| 编号 |
| 禁止 |
| 原因 |

| X36 |
| 禁止让"普通生成"进队列（发送、再来一张、重试都一样） |
| 普通生成是"马上要看到"的操作。塞进队列就变成盯着一条十几分钟不动的进度条，用户以为坏了。忙就直说忙，比默默排队好一百倍 |

| X37 |
| 禁止在 ComfyUI 忙的时候仍然把普通生成提交上去（哪怕只是丢进 ComfyUI 自己的队列） |
| 提交了就算"执行了"，用户会以为马上出片。要求是：忙 → 只提示，不提交、不排队 |

| X38 |
| 禁止把队列生成做成"一次只能有一个"（排了一个就不许再排） |
| 队列生成的用途就是批量跑高清。每点一次都要等上一次跑完，那"批量"两个字就没意义了。必须能连着点，排到队尾 |

| X39 |
| 禁止让队列生成插到普通生成前面，也禁止在普通任务没跑完时接受队列提交 |
| 用户正在等的那一张是"当前的事"，队列是"待办的事"。顺序一反，用户会以为自己的片子丢了 |

| X40 |
| 禁止"点了没反应"：任何被拦下的提交都必须说清是哪个任务在跑、跑到几成 |
| 只说"系统忙"等于没提示。用户需要知道"哦是刚才那张视频在跑，那我等它" |

| X41 |
| 禁止为队列单独做一个页面（"队列管理""任务列表"那一套） |
| 队列的状态就三处：右栏一行状态、右栏一个清单、结果卡头部一个小标签。为此再开一页，等于承认主界面说不清楚 |

| X42 |
| 禁止让【加入队列生成】换种子 |
| 队列生成的用途是"这张样片我要高清版"。换了种子就是另一张画，跟用户挑中的那张没关系了。同一批只能有一个种子，一路用到底 |

| X43 |
| 禁止在卡片上罗列"共 N 个成品""档位 精细 / 默认"、也禁止贴归档路径 |
| 用户看这一批只关心两件事：这张用了什么种子、能不能再来一张。成品数和档位在卡头已有，路径在大图/下载里已有——卡底重复一遍，反而把真正有用的种子挤没了 |

| X44 |
| 禁止在管理台提供"添加工作流""新建能力"这类入口（文件选择框、"＋ 新增"按钮、拖进来一个 json 都算） |
| 能力和它挂的工作流是部署信息，只能写在 config.yaml 里。页面上点出来的东西：换个环境就没了、出了事也说不清是哪次点的。页面只做三件事——开/关、排档位、重读配置 |

| X45 |
| 禁止让"没挂工作流"的能力可点或可编辑 |
| 没工作流就没有参数、没有档位，给一张空表单等于让人以为坏了，还会诱使产品去加"添加工作流"的后门。正确做法：列表里显示「未配置」，整项灰着、不可点，等下个版本开放时再解锁；页面上一个可填可点的控件都没有 |

| X46 |
| 禁止除了【加入队列生成】以外的任何入口把任务排进 ComfyUI 队列 |
| 发送、再来一张、重试都是普通生成：ComfyUI 忙就只提示、不提交、不排队。队列是给"这张我很满意，出一版更高清的"用的，不能让随手点的发送也挤进去等 5 分钟 |

| X47 |
| 禁止让"同时跑几个 / 超时 / 预览帧 / 队列上限"出现在页面上 |
| 一次只跑一个、不设超时（本机直连）、不收预览帧——这三件写死在代码里；队列上限写在配置文件里。这些连只读那一行都不必显示：不会变的事实摆在页面上，只会让人以为需要调 |

| X48 |
| 禁止做"全局负面词" |
| 没有需要"所有图片共用一段负面词"的场景。负面词就在各工作流自己的格子里，跟别的参数一样进档位表 |

| X49 |
| 禁止在自检页逐个检查工作流（节点缺失、模型在不在、档位越不越界、出片节点认没认出来） |
| 自检只做两项：ComfyUI 连不连得上、成果目录写不写得进去。工作流的毛病等真跑一次，ComfyUI 会直接点到具体节点具体那一格。预检做一份"节点对照表"，既慢又不准，还要跟着节点包天天维护 |

查"ComfyUI 现在有没有任务在跑"是允许的（读它的执行队列状态即可），这不等于 X15 说的"做显存守卫"——我们只是如实转达忙闲，不替它调度、不替它降档。

2.4 界面文案：只对使用者说话

判断标准一句话：这句话，一个只想赶紧出图的人看了有用吗？没用就删。

| 编号 |
| 禁止 |
| 说明与改法 |

| X50 |
| 禁止在界面上解释"为什么这么设计"（"页面上不提供……是故意的""这一项不能关——归档是固定行为""这里是避免堆满目录"） |
| 用户不关心设计取舍。只说你现在该做什么。反面例：「页面上不给加，因为这是部署信息」→ 正面：「要加工作流，改配置文件后再点重读配置」 |

| X51 |
| 禁止出现只有做的人懂的词：部署信息、配置文件里的口径、写死、固定行为、后端、服务端、字段映射、归一、拷贝件、静默、回滚、幂等 |
| 用用户自己的说法：文件、配置、按钮、成品、上一版。管理台里可以出现"节点 / 参数 / 工作流"——那是配置的人必须认识的三样东西，且它们是 ComfyUI 里的原词 |

| X52 |
| 禁止解释系统内部怎么实现的（"由服务端按数量动态接""等于把原始工作流深拷贝一份，写进复制件"） |
| 用户只看到结果：勾几个节点右边就出几个参数；填好值点添加就多一档。实现细节一条都不写 |

| X53 |
| 禁止在界面上写"不给 / 不许 / 不能 / 禁止"式说明 |
| 这类句子是写给开发者的约束。界面上要么直接把那个入口去掉，要么用中性陈述代替（"这一档是原文件，改不了"就够了） |

| X54 |
| 禁止一句话里塞两个以上因果链（"因为 A 所以 B，不然 C 会 D，如果要 E 就得 F"） |
| 折成两句短话，或者只留最需要用户知道的那半句。卡片和面板的说明文字，一行不超过 20 个字最舒服 |

| X55 |
| 禁止把"原型 / 演示 / 模拟"写进正式界面的按钮和提示里 |
| 只有开发自己用的调试入口可以说"演示版不做真下载"；正式交付时这些字样全部清除 |

| X56 |
| 禁止让文档里的界面示例和实际画面脱节 |
| 文档插图里的每一句话，都必须能在真界面上原样找到。原型改了口径，插图同步改——文档插图就是开发眼里的需求。适用范围：约束交付给开发的这版文档；探索期给需求方看的演示原型不受此约束。§1.5 的表按「档位参数不进输入区」的口径写 |

X50~X56 的用法：写界面文案时先问一句"这句话是给用它的人看的，还是给做它的人看的"。后者一律搬进文档，不要留在画面上。改完文案后用敏感词扫一遍页面（部署 / 写死 / 固定行为 / 不给 / 原型 / 来自配置文件 / 设计），有命中就重写。

举一个改到位的例子（结果卡底部那一行）：

改前：「这一批都用这个种子，换档位出来的是同一张，只是更精细」——像在给写代码的人解释机制。

改后：「种子 887231456」——用户要的只是这个号，能复制、能记住；"同一张更精细"这件事，按钮旁边写"加入队列生成"就够了。

三、配置与存储：只维护当前状态

| 编号 |
| 禁止 |
| 说明 |

| X8 |
| 禁止做多版本对比、历史版本列表、一键回滚 |
| 只维护一个当前版本。想留底就手动导出文件 |

| X9 |

| X10 |

四、文件系统：只在成果目录和拷贝目录里动

| 编号 |

七、一句话总结

这个应用只做一件事：把 ComfyUI 的工作流包装成"会用斜线技能的 AI 能直接点的一道菜"。

界面要极简（描述框 + 档位），配置要极简（选文件 + 勾几个节点 + 填值点添加），存储要极简（单配置文件 + 一堆工作流拷贝），接入要唯一（斜线技能）。

档位里有哪些参数，永远是这个工作流决定的，不是程序决定的（X21~X33）。这一条弄反了，每加一个新工作流都要回来改代码，那就白做了。

配置页只有一件事要做：让用户看清节点、勾出该给用户的那几个、再给它们造几档。 造档的方式是"复制一份工作流"，不是"填一张表"——这样每一档天然就是一份能直接发出去的工作流，不需要运行时再拼。

原始工作流永远是默认档，永远是只读的基准（X27 / X35）。所有"改"都发生在拷贝上。

普通生成忙了就拦住，队列生成才允许堆积（X36~X41）。这两条反过来，用户要么在等一张本该 6 秒出的图，要么得守着一张一张点高清。

一批一个种子，队列只换档位不换种子（X42 / X43）。种子一换，"再来一版高清的"就变成了"再画一张，随便吧"。

任何让上述四件事变复杂的需求，先回到这一章对一遍。

Q4　这次哪几处是我的建议，你可以否决

| 建议 | | 理由 | | 否决的后果 |

| 页面由后端进程直接发出（只跑 1 个进程，不是 2 个） | | 前端就是一个静态文件夹，单开一个服务只多占几十兆内存 | | 多一个进程和一个故障点，对你"把资源留给 ComfyUI"没有好处 |

| 能力清单做得很短（不是完整参数说明） | | 清单每次都要被 AI 读进上下文，越长越慢。短才快 | | AI 每次思考多花 1~3 秒，抵消掉这一层的意义 |

| 16 个能力入口先建好、标"未配置" | | 你能看见"还差什么"，体系是完整的；灰色不碍事 | | 也可以完全不显示，但你就失去了"还差哪些"的清单感 |

Q5　还有 3 个问题需要你确认

① 工作流 json 放哪儿？放在应用自己的 workflows 目录（换机器整包拷走），还是直接指向 ComfyUI 的工作流目录（改完不用另存）？两种都支持，只是默认值不同。

② 你手上现在有几个能跑通的工作流？如果只有 1~2 个，第 2 阶段就用它做通道验证；如果还没有，我建议第 1 阶段先把管理台做扎实，工作流边做边加。

③ 前端视觉偏好？文档里的页面示意图是"蓝白、克制、偏工具感"。如果你喜欢更活泼的（彩色图标、卡片更大），可以在开发前定一下，后面改样式成本较高。

下一步：这版文档如果方向对，我就按第 05 章的阶段 1 开始动手——先出一个"能配不能生成"的骨架：能打开、能在管理台新增能力、选工作流、勾参数、保存，创作台能看到参数条。那时候你就能真正上手点一遍，比看文档更直接。
