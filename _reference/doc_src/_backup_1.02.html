第 01 章产品定位与边界

一、这是什么

类比：ComfyUI 是一台"会干活但听不懂人话"的机器，WorkBuddy 是一个"听得懂人话但手很慢"的助手。本应用就是中间那个"车间主任"——听一句指令，立刻分配机器、装好参数、盯着干完、把成品端出来。

二、为什么要多这一层（核心论据）

你说的"WorkBuddy 直连 ComfyUI 也行，但太慢"，这个判断是对的。我把"慢在哪"画出来：

2.1 一句话总结

把"准备和等待"从 AI 的推理循环里，挪到本地进程的内存里。

本机做这些是毫秒级，AI 做这些是秒级。这就是全部价值。

三、边界：一件事只归一个人管

3.1 校验方式：越界了会怎样

如果…… 说明越界了 正确做法
应用去扫描 models/ 目录 越界（这是 ComfyUI 的地盘） 不做。模型名对不对，提交时由 ComfyUI 说了算
应用去启动 ComfyUI 越界（前提是它已启动） 只检测"连不连得上"，连不上就提示用户
应用把成果物归档到指定的成果目录 不越界（这是明确要求，见 3.2） 生成成功后移动到 成果目录/能力名/ 下
应用把成果物复制到成果目录以外的任何地方 越界（多余动作，还费磁盘） 只在成果目录内移动，不另存副本
应用删除或改动 ComfyUI output 里不属于本次生成的文件 越界（动了别人的东西） 只处理自己刚刚生成的那几个文件
应用因为"显存不足"自动降分辨率重试 越界（性能是它的事） 把失败原因说清楚，让用户或 AI 决定怎么办
应用读工作流的 json 不越界（这是你放进来的配置） 必须读，否则不知道怎么填参数

3.2 成果物为什么要归档（这是明确要求）

ComfyUI 默认把所有结果都吐在 output/ 根目录里，用久了就是一片乱麻：图片、视频、音频混在一起，文件名还是 ComfyUI_00012_.png 这种流水号，根本看不出哪张是哪个功能生成的。

所以要归档。规则如下：

项 规定
默认位置 ComfyUI 的 output 目录 / ComfyBridgeOutput /
可改 管理页可以指定成别的目录（比如换一块大盘）
再按能力分 每个能力一个子目录，名字就用能力名，比如 图片生成/、9 宫格故事板/、视频生成/
最终样子 output/ComfyBridgeOutput/图片生成/xxx.png
谁动手 应用在后端移动文件，用户无感
动哪些文件 只动本次生成产生的那几个，别的一概不碰

为什么这条不算"越界"：越界的定义是"插手 ComfyUI 自己的事"。output 里的成品是给用户看的产出物，把它们收拾整齐是这个应用的本职。但边界依然存在：只在成果目录里动，成果目录以外一个字节都不碰。

五、成功的标志

第 02 章核心机制（图形说明）

一、先回答那个疑问：调用工作流到底要什么？

1.1 ComfyUI 的接口要的是"图纸"，不是"文件名"

1.2 一句话记住

工作流文件 = 图纸。ComfyUI 要的是把图纸摊开（读成数据）递过去，不是告诉它图纸放哪。

所以应用一定要"看得懂"图纸，才知道用户的文字填到图纸的哪一格。看不懂图纸，就只能让用户自己去 ComfyUI 里跑，那就没有意义了。

1.3 你的"一个一个加"是什么意思

你每加一个工作流，实际要做的事是：

1.4 档位到底"存"在哪：一档 = 一份工作流拷贝

这是全篇最容易做错的一处，所以单独讲一遍。

先说结论：

默认档 = 你从 ComfyUI 导出的那个原始工作流，一格不改，只读、只调用、删不掉。 用户想要的每一档 = 把原始工作流复制一份，把这一档要改的几个参数写进这份复制件的对应节点。 这份复制件就是这一档要调的工作流。

这样做的直接好处：档位不需要一张"值表"，每一档本来就是一份完整、能直接发给 ComfyUI 的工作流。

1.4b 例外：角色设定图的档位不拷文件，只叠参数

上面说的"一档 = 一份工作流拷贝"适用于图片生成这类能力：档位少、彼此差别大、想改就整份改。但角色设定图有 18 个组合（版式 × 画法 × 参考方式），每个组合再拷一份文件会把目录塞满，而且 18 份内容和版式强绑定、改版式就会全部作废。

图片生成这类能力角色设定图
一档是什么一份工作流 JSON 拷贝，参数直接写进拷贝一组"相对默认档改了哪些值"的叠加参数（overlay），不产生新文件
存在哪workflows/ComfyBridge/ 下的拷贝文件config.yaml 的 sheetGrades 段，按组合 id 分组
画幅从哪来档位自己写宽高/倍数由版式算出来（四视图 16:9 / 四宫格 1:1 / 单张全身 9:16），档位只能改像素与倍数，改不动比例
每次生成怎么用直接提交那份拷贝按当前版式现算一份完整配方，再把档位的叠加值盖上去，然后提交
默认档叫「默认」，只读不可删同样叫「默认」，只读不可删；改画幅请改版式

一句话：图片生成的档位是"另存一份"，角色设定图的档位是"在本子上记一笔改了什么"。两者在创作台上长得一样（一排档位按钮），实现上完全不同——文档里必须分清，否则加了新能力会选错模型。

1.5 谁该出现在"可设置"清单里

不是工作流里所有节点都值得让人设置。有三类节点改了没意义，所以管理页压根不列出来：

节点类型 典型节点 为什么不列 谁负责它
提示词 CLIPTextEncode / MusicGenTextEncode 内容是用户在创作台现打的，不是配置项 创作台的大输入框（配置页里只绑"绑到哪一格"）
上传参考 LoadImage / LoadAudio / LoadVideo 用户上传几张就有几个，数量不固定，由服务端按数量动态插入节点 创作台的上传按钮 + 服务端动态拼
出片 SaveImage / SaveVideo / SaveAudio / PreviewImage 只负责把结果拿出来，没有"选哪个值"这回事 按 class_type 自动认，配置页不选、也不列

剩下的参数节点才列在清单里，勾哪个，哪个的参数才出现在设置区。

1.6 参数是什么形态，就用什么控件

同一个工作流里，参数天生分成好几种。控件的形态跟着参数的形态走，不是一律给输入框：

参数形态 长什么样 用什么控件 例子
整数 / 小数 一个数字 输入框（数字），带步长和上下限 步数 28、CFG 7.0、时长 30
是 / 否 两个状态 开关 音画同步、是否保留原图
枚举（只能选一个） 一串固定选项 选择菜单（下拉） 采样器 dpmpp_2m、调度器 karras、音色、分辨率 720p
枚举（能选好几个） 一串可多选的选项 多选 IPAdapter 的组合方式 concat / add / average
一段文字 一到多行文本 输入框（文字 / 多行） 文件名前缀、分镜描述

一句话记住这三条：

默认档就是原始工作流本身，只读、删不掉。

每加一档 = 复制一份工作流，把这档要改的值写进复制件。

提示词 / 参考素材 / 出片三类节点不给设；能设的参数，形态是什么就给什么控件。

1.7 应用只做这几件事

接收 → 填表 → 提交 → 盯住 → 取回 → 归档 → 转达

除此之外的事，一律不做。（具体哪些不能做，见第 07 章"禁止事项"。）

三、从点"发送"到看到图片，中间发生了什么

3.1 一个容易被忽略的小事：怎么知道"哪个文件是成品"

一个工作流跑完，可能产出好几个文件：中间图、放大前的图、最后成品。应用不能把中间产物也发给用户。

3.2 两种提交：普通生成 与 队列生成

同一个"提交"动作，在这个应用里被分成了两条路。分不分，决定了用户等 6 秒还是等 40 分钟。

两条路的分工，一句话就能说清：

普通生成 队列生成
用户的期待 马上看到，好不好再调 反正要跑很久，一次性丢过去
所以 绝不能排队，忙了就直说 必须能堆，堆完一个接一个跑
谁在等 用户本人盯着屏幕 用户可以关掉去看别的，回来看结果

还有一个前提：同一批只用一个种子。

队列生成不是"再画一张"，而是"把这张画得更细"。种子必须沿用——种子一换，出来的就是另一张构图，用户挑中的那张就没了。所以成品块上写的是尺寸（1024×1024 / 1344×768），而不是每格一个种子：种子整批一样，逐格写反而看不出差别。

这两条要是搞反了（普通生成也进队列、队列只许一个），这个功能就白做了：前者让"快速出图"变成"排队等图"，后者让"批量跑高清"变成"守着一张一张点"。

六、外部怎么调用（给 WorkBuddy 这类软件）

6.0 外部接入只有一种：斜线技能

本项目对外只提供一种调用方式——在支持斜线技能的 AI 客户端里输入 /，从下拉窗选中对应技能，然后用自然语言描述需求。

没有第二种方式。以下这些明确不做：

不做的事 说明
不做 MCP 服务 无论 MCP 多方便，本项目不实现 MCP 端点
不鼓励外部程序直接调 HTTP 接口 内部接口存在是因为技能要用它，但不当作对外接入方式宣传，也不提供对接文档
不做 OpenAI 兼容接口、不做插件市场、不做命令行工具 同上，一律不在范围内

为什么要写死这一条：方式一多，就要多维护一套文档、多测一遍兼容性，还容易让人以为"随便什么程序都能接"。只有一种方式，边界最清楚。

6.1 AI 只需要 3 类请求

请求 它问什么 它得到什么
看菜单 "你都会做什么？" 一页清单：能力名 + 这个能力有哪几档 + 大概多久
下单 "按这个要求做一张" 一个任务编号 + "过多久来问一次"
取货 "刚才那单好了吗？" 进度 / 成品地址（已归档到成果目录）/ 失败原因

为什么这就够快：AI 不问"你的工作流长什么样"、不问"你装了哪些模型"、不读任何文件、不写任何脚本。它只做三件事，剩下的全在本地进程的内存里完成。

第 03 章功能规格

一、创作台（日常使用的那一页）

1.1 页面布局

布局硬性要求（踩过坑，写进规格）

这页不能用"固定高度 + 内部各自滚动"的做法。那种做法在有些嵌入环境（如预览面板、iframe、某些客户端的 WebView）里会出现滚轮失效、也没有滚动条的假死现象，用户以为页面卡住了。

正确做法是整页滚动：

元素 规则
页面本身 可以滚动，内容长了就出滚动条，滚轮始终有效
顶栏 顶部吸附，滚动时不消失
左侧能力栏 / 右侧任务栏 各自吸附在顶栏下方；内容超长时栏内可滚，不影响整页
中间对话区 跟整页一起滚，不做内部滚动容器
底部输入区 吸附在窗口底部，滚到哪儿都在，随时能输入

一句话判断标准：在任何窗口高度下，滚轮都要能滚，并且一定能看到滚动条。

1.2 每个区域干什么

区域 作用 关键规则
顶栏 一眼看健康状态 ComfyUI 断了就是红灯，不假装能用
左侧能力栏 有哪些能力 只显示"已配好工作流"的能力；没配的显示灰色"未配置"（让人知道有这个功能，只是还没接）
中间对话流 主战场 一次提交一张卡：生成中显示步骤和进度条，完成后就地变成成品，失败后变红并给原因；同一张卡可以接多个成品（见 §1.6）
右侧抽屉 本次会话的任务清单（全选 / 批量删除） 点一条可以跳回那条卡片。手机端它收成一个图标按钮，点一下从右侧滑出，占屏幕右侧一条（见第 08 章）
输入区 写描述 + 选档位 档位按钮随能力变化；不带图片/文字时按能力校验

1.3 交互细节（25 条，逐条验收）

# 场景 应有的表现
1 点发送 立刻出现"用户气泡 + 生成中卡片"，输入框马上清空可继续写
2 生成中 显示"第几个节点、第几步 / 共几步"、进度条、已用时间；不显示预览小图（预览帧很吃存储，明确不要）

4 失败 卡片转红，上面一行人话（"ComfyUI 在 K采样器 报错：显存不足"），下面一行"展开详情"看原文
5 失败时给动作 提供"重试一次"（不修改参数）、"降一档重试"（仅当还有更低一档）

7 悬停成品 出现 下载 / 加入队列生成 / 复制种子

12 切换能力 输入框提示语、档位按钮、示例提示词全部随之变化；已写的内容按能力分别存草稿，切回来还在
13 默认档位 每个能力都标好一个默认档（一般就是"均衡"），用户不选也是这一档
14 空描述 若能力要求必填描述且为空，发送按钮置灰 + 一行浅灰说明
15 多轮微调 提供"基于上一条再来一张"的小按钮，点了会把上一条的描述和档位带过来
16 长任务 视频类可能几分钟，卡片上显示"已用 3 分 12 秒"，允许关掉页面，回来还能看到（任务在服务端跑）
17 切换页面 从创作台点"⚙ 管理台"再回来，任务状态不丢

23 队列里已有任务时再点【加入队列生成】 允许，接着排到队尾，可以连着点；提示"前面还有 N 个"
24 有普通生成没跑完时点【加入队列生成】 只提示，不加入。等普通任务跑完才能加
25 队列生成本身 不换种子。同一批里挑不同档，出来的都是同一张的不同精度版本；卡底始终只显示那一个种子

1.4 输入区长什么样（以图片生成为例）

只有三样东西：一个描述框、一排档位、一个发送键。 没有步数、没有 CFG、没有种子、没有采样器。

三条规则

  1. 技术参数一律不给用户看。 具体是哪几个参数、叫什么，全部藏在工作流和档位里，界面上只出现档位名。
  2. 要调就调"档"，不是调"参数"。 一个档 = 一次把好几格一起改掉。勾进来的那几格同时变，由一个动作完成。
  3. 档位是"这个工作流自己声明的"，不是全项目统一的。 图片可能是「快速 / 均衡 / 精细」，视频可能是「草稿 / 成片」，音乐是「短一点的 / 标准 / 完整一段」，语音可能干脆没有档位。 具体有几列、每列是什么，由工作流里实际存在的格子决定（见 02 章 §1.4），程序里不预设任何一列。

1.5 每个能力的入口控件，按能力单独定

这是硬规定：每加一个能力，它的输入区长什么样要单独设计，不能套模板。

能力 输入区大概长这样（示例，实际以那个工作流有什么节点为准） 档位里大概勾哪几个节点
图片生成 画质三档 + 描述框 尺寸节点 + 采样器节点 → 出来是宽/高/步数/CFG
参考风格生图 参考图上传 + 画质三档 + 描述框 尺寸节点 + 参考强度节点 + 采样器
线稿图生成 源图上传 + 线条风格（两种选一）+ 描述框 尺寸节点 + 采样器（线条风格单独一档）
简单手绘创作 草稿图上传 + 「像原图 ↔ 像成稿」两档 + 描述框 尺寸节点 + 采样器（要改"改写幅度"就勾它）
角色设定图 四个分段按钮（版式 / 画法 / 参考）+ 档位 + 描述框；选完就是个具体组合，比如「单张全身 · 彩色 · 锁定同角色」 像素与倍数两个节点（宽高比由版式算，不给勾）+ 采样器
宫格故事板 格数选择 + 分格描述 + 描述框 只要采样器也够用——别为了"齐整"硬凑宽高
视频生成 时长 + 画质两档 + 描述框 视频采样节点 + 采样器 → 宽/高/帧数/步数
首尾帧生成视频 首帧图 + 尾帧图 + 描述框 首尾帧节点 + 采样器
音乐生成 描述框 + 两三档 只要音乐采样节点 → 时长 / 速度（没有宽高）
语音生成 音色 + 文本 可能一个节点都不勾（没有档位）
声音克隆 参考音频上传 + 要念的文本 常常也没有档位

最后一列只是"通常这么勾"，不是规定。同一个能力换了工作流（比如挂上加速 LoRA），可勾的节点就变了——重新勾一遍即可，程序不动。

为什么列这张表：防止后面的开发图省事，给 17 个能力套同一个"万能表单"。每加一个能力，都回到这张表更新它那一行。

已经越过这张表的只有两个能力：图片生成和角色设定图。前者的输入区就是「模式 + 档位 + 描述框」，后者是「四个分段按钮 + 档位 + 描述框」，两者都按上表单独设计过，没有互相套用。剩下 15 个能力还没接工作流，接的时候照这张表逐个定，不要复制粘贴图片生成那一套。

判断一个控件该不该出现在界面上的标准，问三句话：

  1. 不懂 ComfyUI 的人，看到这个词知道该怎么选吗？（不知道 → 不给）
  2. 这个值改了，用户能从结果里直观看出区别吗？（看不出 → 不给）
  3. 这个值需要和别的值一起改才有意义吗？（是 → 打成一个档，别拆开）

1.6 结果卡长什么样：一次出一张，队列往后接

一张卡 = 一次提交。 卡里可以有不止一个成品：第 1 个是普通生成出来的，后面几个是点【加入队列生成】一张一张接上去的。

五条规则

# 规则
1 卡里第 1 个成品永远来自普通生成；后面的成品只可能来自【加入队列生成】。不允许"一次普通生成出好几张"这种多入口
2 一批只有一个种子。 普通生成时随机出一个，之后这一批里所有队列任务都沿用它。所以成品 2、成品 3 跟成品 1 是同一张构图，只是用了更高的档（尺寸更大、步数更多）
3 队列还没出片时，卡里就占一个虚线占位块，写着"成品 3 · 排队中，前面还有 N 个"。用户在点完的一瞬间就知道自己排到了第几，不用去别处查
4 占位块从"排队中"变"正在采样 60%"再变图，全程在同一张卡里，不新开卡、不跳位置
5 卡底只留一行：种子 + 【加入队列生成】【↻ 再来一张】。不写"共 N 个成品"、不写"档位 精细 / 默认"、不贴归档路径——这些信息分别在卡头、大图、下载里

成品块上写什么：第一行 成品 N，第二行写这一档的尺寸（如 1024×1024 / 1344×768）。因为种子整批一样，写种子反而每格都一样、看不出差别；写尺寸才一眼看出"这格更精细"。

只有跟基准档不同的那几格，左上角才多一个小档位标签（如"精细"）。基准档不加标签，否则每格都挂一个，反而吵。

为什么不给每个成品单独开一张卡？因为用户是按"这句话"记事的，不是按"第几次提交"记事的。同一句话的 4 个版本散在 4 张卡里，翻起来比不生成还累。

1.7 两种生成：普通生成 与 队列生成

这是这一页唯一的"硬规则"，所有会提交任务的地方都要按它判断，包括图片、视频、音乐、语音、故事板。

普通生成 队列生成
入口 发送键（↑ 或 Ctrl/⌘+Enter）、卡片的【🔁 再来一张】、失败卡的【重试一次】 已完成卡片底部的【🕒 加入队列生成】
什么时候能点 ComfyUI 空闲（当前一个任务都没在跑） 没有普通生成没跑完
ComfyUI 正忙时 弹一条提示，说清"谁在跑、跑到几成"，不提交、不进队列 允许。排到队尾，可以连着点好几个
出片落在哪 新开一张卡，里面是成品 1 加进同一张卡，成品 2、成品 3…
种子 新随机一个 沿用这一批的种子，只换档位（同一张的高清版）
典型用途 试描述、试档位，要立刻看到结果 挑几张满意的，批量跑高清精品

为什么普通生成坚决不进队列

普通生成本来就是"快出片"用的。把一次普通生成塞进队列，用户会面对一条十几分钟不动的进度条，还以为坏了——这比直接告诉他"现在忙，等会儿"体验差得多。所以宁可拦住，也不排队。

为什么队列生成必须能连着点

高清精品一张就要跑很久。如果每点一次都得等上一次跑完才能点下一次，那"批量"就没意义了。所以队列是允许堆积的：点一次加一个，全部排在后面，一个跑完自动接下一个，人可以去干别的。

三种会被拦住的情况（都要写清"是谁在跑"）

场景 提示里必须有的信息
普通生成撞上正在跑的任务 在跑的是哪个能力、哪一档、到几成了；并说明"这次不提交，也不排队"
加入队列生成撞上没跑完的普通生成 同上，并说明"队列生成要等普通任务结束才能加"
ComfyUI 没连上 直接说没连上，先启动 ComfyUI。不要假装提交了

队列在页面上出现在三个地方：右栏顶部的一行状态（空闲 / 正在跑哪一档）、右栏的"执行队列 N 个"清单（第 1 个、第 2 个…）、卡片头部的一个小标签（队列 1 个 · 正在出成品 3）。三处都指向同一件事，用户在任何位置都不会以为"点了没反应"。

二、管理台（配置那几页）

管理台永远是左侧菜单 + 右侧表单，一共 5 页：能力与工作流 / 档位表 / 设定图模板 / 服务设置 / 自检。其中「档位表」下面还挂着能力子菜单，点一下就直达那个能力的档位表，不用先进列表再点配置。

这张图里的每一个字，都是使用者在该页会看到的样子。不给使用者看的东西不进画面：哪个能力挂了几个工作流、工作流叫什么文件名、档位是怎么拷出来的，一律不显示——它们属于配置文件，属于实现，不属于界面。

2.1 页面一：能力与工作流

你能做的 细节
能力从哪来 只来自配置文件（config.yaml 里的能力清单）。页面上不提供"新增能力"，更不提供"添加工作流"
工作流从哪来 配置文件里每个能力下面写 1 个或多个工作流文件名。页面不展示工作流清单、不展示文件名、不展示挂了几个——使用者只需要知道这个能力能不能用、有哪几档
能力信息 名字、图标、一句话介绍全部来自 config.yaml，页面上只读不可改。这一页不提供新增、复制、删除能力——能力清单是部署信息，改它请改配置文件后重启
启用/停用 停用后从创作台消失，但配置保留；没挂工作流的能力不能启用
排档位 只有挂了工作流的能力才能点「配置」。没挂的不显示按钮，只有一行「未配置（下个版本开放）」
直达某个能力的档位表 左侧菜单的「档位表」下面挂着能力子菜单（当前是图片生成 / 角色设定图），点一下直接进那个能力的档位表；已经在这张页面时，子菜单会高亮当前能力

常见能力名（照抄到配置文件里即可，不是页面上的模板）：图片生成、参考风格生图、线稿图生成、简单手绘创作、角色设定图、场景设定图、道具设定图、4 格故事板、6 格故事板、9 格故事板、视频生成、参考生成视频、首尾帧生成视频、音乐生成、参考生成音乐、语音生成、声音克隆。

一个能力实际能干什么，取决于配置文件里给它挂了哪个工作流。每个能力的输入区具体长什么样（几个上传位、几档、有没有开关），都要你按 1.5 那张表单独定，没有现成的参数。

2.2 页面二：档位表（核心页面）

这个页面只做两件事：① 勾出哪些参数给用户调；② 把用户要的那几档"造"出来。 工作流文件和出片节点都不用在这里选——启动时从服务自己的工作流目录自动读取。图片生成这类能力，一档 = 一份工作流拷贝；角色设定图这类组合式能力，一档 = 一组叠加参数（见第 02 章 §1.4b）。

六个设计要点

要点 做法
一档 = 一份工作流拷贝 点【添加】时，系统把原始工作流整份复制到 ./workflows/ComfyBridge/，文件名带档位名（如 文生图.sdxl__快速.json），再把 ④ 里填的值写进这份拷贝的对应节点。这份拷贝就是这一档运行时真正提交的工作流——档位不需要另存一张"值表"。
默认档 = 原始工作流本身，只读 ⑤ 的第一行永远是「默认」，它就是那个原始文件，一个字节都不改。不能改名、不能删、参数控件全部禁用。用户点「默认」= 原样跑一次。这样任何一次失败都能立刻分清是"工作流本身有问题"还是"某一档配错了"。
④ 是"造档位"的地方，不是"选档"的地方 ④ 里只有两样东西：勾中的节点参数 + 档位名称输入框 + 【添加】。它和创作台的档位按钮没有任何关联——你在 ④ 里填的是"下一个档位长什么样"，填完点添加才会变成一档。
⑤ 是列表，不是表格；一档一行 一行 = 档位名 + 改动项数 + 【✎ 编辑】+【✕ 删除】。点【编辑】，这一档那份拷贝的全部参数展开在下面，可以接着改任何一格。默认档那行只有【👁 查看】和一个禁用的 ✕。
提示词 / 参考素材 / 出片节点不进清单 ② 只列参数节点。提示词由创作台填（服务端按字段名自动认出那个文字格子）；参考图/音频数量不固定，由服务端按用户上传的数量动态插入对应节点；出片节点（SaveImage / SaveVideo / SaveAudio / PreviewImage）由服务端按 class_type 自动认，页面上不选。这三类连复选框都不给，避免有人去填一个没用的值。
工作流文件不用选、不用改路径 ① 只显示文件名和"自动读取"标签。每个能力用哪个工作流是固定的，文件放在服务自己的工作流目录里（配置里登记一次），启动时自动读、读完节点就摊在 ②。页面上没有"选择文件""重新读取"，也没有可编辑的路径框——想换工作流就改配置文件里那一行的文件名，页面上没有"选文件"这一说。

参数用什么控件，看它本来是什么形态

参数形态 控件 在页面上长什么样

你想调的东西，脑子里本来就是"我要改采样器那几步"、"我要改空 latent 的尺寸"。按节点勾，配置时不用在十几个字段名里翻；换工作流也不用重新认一遍字段名——节点名在 ComfyUI 里本来就看得见。

2.3 这个页面怎么用（五步）

配一个工作流：自动读取 → 勾节点 → 加档位 → 试跑 → 保存。页面上从左到右、从上到下就是这五块，编号直接印在标题里，不用记。

块你在这一步做什么细节

页面顶部那条切换带

二、第 3 步：先勾节点，再加档位

这一步分两小步，顺序不能反。 先决定"这个工作流里哪几个参数节点该给人调"，再决定"加几档、每档填什么"。

2.1 第一小步：勾节点

读进工作流后，页面左下会把参数节点列出来（编号 + 类型 + 它自己带的参数）。可以多选。

勾中一个节点 = 它身上的全部参数进入设置区。勾了 KSampler，就是种子/步数/CFG/采样器/调度器/改写幅度一起进来，不用一格格挑。

勾哪几个？ 想两件事：

问自己 勾还是不勾
这个节点上的东西，改了用户能看出区别吗？ 看不出 → 不勾（比如 Checkpoint 加载、VAE 解码、文件名前缀）
这些值必须一起改才有意义吗？（比如宽和高） 是 → 勾它，因为它天然打包在同一档里

勾几个？ 1~3 个节点最舒服。一个都不勾也完全合法——那就是"这个工作流只跑默认档"，最朴素的语音合成常常如此。

2.2 常见的勾法（只是经验，不是规定）

工作流长什么样 通常勾哪几个节点 就会出现哪些参数 为什么
普通文生图 尺寸节点（EmptyLatentImage）+ 采样器（KSampler） 宽 / 高 / 张数 / 步数 / CFG / 采样器 / 调度器 一起变才有"快速/精细"的区别
图生图 / 重绘 缩放节点（ImageScale）+ 采样器 宽 / 高 / 改写幅度 / 步数 / CFG 改写幅度是这类能力的命门
参考图（IPAdapter 之类） 尺寸 + IPAdapter 节点 + 采样器 宽 / 高 / 参考强度 / 参考方式 / 步数 强度和方式决定"像不像参考图"；参考方式还是个下拉
绑了加速 LoRA（LCM / Turbo 等） 采样器 + LoRA 节点（宽高常常不用动，不勾） 步数 / CFG / LoRA 强度 加速模型只吃 4~8 步、CFG 1~2；40 步反而是有害配置
视频（有 length / fps） 视频节点 + 采样器 宽 / 高 / 帧数 / 步数 / CFG 帧数直接决定时长和显存
音乐（MusicGen 这类） 音乐采样节点 + 音乐加载节点 时长 / 速度 / 输出设备 / 风格（下拉） 没有宽高、没有步数，硬塞就是废列
语音 / 声音克隆 加载节点 + TTS 节点 音色（下拉）/ 语速 这类给的是"音色"，不是画质档
参考生成视频（多图 + 多音频） 视频节点（H3 这类） 时长 / 分辨率（下拉）/ 动作幅度 / 音画同步（开关） 这是唯一会出现开关的典型场景

注意"加速 LoRA"这一行：同一个能力换成一个绑了加速 LoRA 的工作流之后，该勾的节点本身就会变——原来勾「尺寸 + 采样器」，这时只要「采样器 + LoRA」。 这正是为什么不能写死——节点是跟着工作流走的，工作流一变就回左边重勾一遍。 演示原型里「图片生成」下面就有这么一个工作流（文生图.sdxl.turbo），可以直接点开看差别。

2.3 第二小步：加档位

勾完节点，④「新增档位」里会出现每个节点一块参数，每个参数按它自己的类型摆控件：

参数类型 长什么样 例子
数字 输入框，能上下调，旁边标范围和步长 步数 28、CFG 7.0、帧数 81
是 / 否 开关（绿=开，灰=关） 音画同步
枚举单选 下拉菜单，选项来自工作流本身 采样器 dpmpp_2m、分辨率 720p、音色
枚举多选 勾选框列表 IPAdapter 的组合方式
文字 文字输入框（长的会自动变多行） 文件名前缀、画风描述

在 ④ 里填好一组值、在下面写上档位名、点【＋ 添加】：

⑤ 里是已有档位的列表，一行一档：

列表里的东西 是什么 一定要填吗
第 1 行「默认」🔒 原始工作流本身。不能改名、不能删、参数控件全灰、只能点【👁 查看】 自动存在，不用管
档位名 用户看到的那两三个字：快速 / 精细 / 草稿 / 成片 必填（重名会被拦）
拷贝 N 项改动 这一档相对原始工作流改了几个参数，一眼看出"这档到底改了什么" 自动计算
【✎ 编辑】 点开，这一档那份拷贝的全部参数展开在下面，可以接着改任何一格 —
【✕ 删除】 删掉这一档，它那份工作流拷贝也一起作废 —
一句话说明 给用户看的一行小字，解释"选这档会怎样" 建议填

为什么默认档必须存在：任何时候出问题，你都能让用户点「默认」跑一次。它跑通了 → 问题在某一档的值上，去改那一档；它也跑不通 → 问题在工作流本身，跟档位无关。少了这个基准，排查会加倍痛苦。

2.4 哪些节点根本不会出现在清单里

这三类节点改了没意义，所以连复选框都不给：

节点类型 典型节点 为什么不让设 谁负责
提示词 CLIPTextEncode / MusicGenTextEncode / 各类 text encode 内容是用户在创作台现打的，不是配置项；每档写死一句提示词没有意义 创作台大输入框；⑥ 只绑"绑到哪一格"
上传参考 LoadImage / LoadAudio / LoadVideo 用户传几张就有几个，数量不固定，要由服务端按数量动态插入并连线 创作台的上传按钮 + 服务端动态拼
出片 SaveImage / SaveVideo / SaveAudio / PreviewImage 只负责把结果拿出来，没有"选哪个值"这回事 按 class_type 自动认，配置页不列、不选

剩下的才是参数节点。没勾的参数节点不会消失——它照样在工作流里跑，值用 json 里的原值，用户在创作台永远看不到。

参数 勾不勾 为什么
Checkpoint 加载（模型文件名） 不勾 换模型 = 换工作流，不该给用户挑
LoRA 名字 不勾这一格，勾节点也行 名字给用户看没意义；名字这格在下拉里改一下就行，但通常不用动
采样器 / 调度器 勾进来没关系 它们在档位里变成下拉菜单，用户看不懂就不看
种子 勾不勾都行 一般留随机；要复现就在结果卡上点"复制种子"
文件名前缀 不勾 归档时应用自己接管
VAE 解码、预览节点 不勾（没有可调的值，也不会出现在清单） —
张数 / 批次 不勾 一次出几张由工作流定，不做成用户选项

2.5 描述框绑到哪

一个工作流只有一个描述框。这个格子不用你在页面上选——读工作流时就自动认出来了，认的规则是"排除掉别的东西之后，唯一那个文字格子"：

工作流 自动认到的格子
文生图 正向 CLIPTextEncode 的 text
故事板 StoryboardGrid 的 cells
视频 提示词节点的 prompt
音乐 音乐编码节点的 prompt 或 genre

（负向提示词的 CLIPTextEncode 会被排除；一个工作流里要是有两个正向文字格子、认不准，服务会按节点编号取第一个，建议你在 ComfyUI 里合并成一个再导出。）

负向提示词不放描述框（用户写不好负面词）。它就在工作流自己的那个负面词格子里，跟别的参数一样进档位，每档可以不一样。

2.6 换工作流 / 改工作流之后怎么做

这是最容易出事的场景，单独列出来。

情况 会发生什么 怎么办
把工作流文件换成新版（节点名变了） 老节点在新清单里已经没有了，勾自然失效 回左边 ② 按新清单重新勾；旧档位只剩默认档，重新加
在原来基础上加了一个 LoRA 节点 节点清单里多了一行 LoraLoader 在 ② 里勾上它，④ 里就多出 LoRA 强度那一格，加档时填上
想少给用户一个参数 取消勾这个节点 它的参数立刻从 ④⑤ 消失，各档拷贝里对应的值一起清掉
只想设节点里的一格（比如只要步数，不要种子） 做不到，也不建议做 一个节点是成套的。真要拆，就在 ComfyUI 里把想分开的参数拆到两个节点，再重新导出
某一个档想推倒重来 删掉这一档，重新在 ④ 填一次 默认档不受影响，因为它从来没被改过
完全不想要档位了（比如改成语音） 一个节点都不勾 ④ 显示空态，⑤ 只剩默认档，创作台只有一个默认按钮

不需要改程序，也不应该改程序。 如果某次换工作流时你发现"非改代码不可"，说明读工作流的逻辑有问题，回去修那个，别改档位的结构。

现象 原因 怎么办

三条纪律：

  1. 拷贝目录整个是应用自己的地盘，不要手工编辑，下次保存会被覆盖。
  2. 原始工作流永远不被写。想改原始值，回 ComfyUI 重做、重新导出。
  3. 换工作流时，旧拷贝已经对不上新节点，保存时会被提示"有 N 个档位要重建"，选重建即可。

第 07 章禁止事项（写死，不要自行发挥）

这一章是给后来接手的人或 AI 看的。如果你没有参与过前面的讨论，只拿到这份文档，请把这一章当成硬约束：下面每一条都是明确决定过的"不做"，不是"还没决定"。

看到"可以优化一下"的冲动时，先回来对照这一章。

一、接入方式：只允许斜线技能

编号 禁止 说明
X1 禁止实现 MCP 服务 无论 MCP 多流行、多方便，本项目不提供 MCP 端点，也不做 MCP 相关的配置项
X2 禁止把 HTTP 接口当对外接入方式 内部接口存在只是因为斜线技能要用；不写对外对接文档、不做 API 使用示例、不在界面上宣传
X3 禁止做 OpenAI 兼容接口 / 命令行工具 / 浏览器插件 一律不在范围内

唯一合法的使用姿势：在支持斜线技能的 AI 客户端里输入 /，从下拉窗选中技能，然后用自然语言描述需求。

二、界面：技术参数不对最终用户暴露

界面上的每一句话都是写给"用它的人"，不是写给做它的人。 这条比下面任何一条都容易违反，所以单列一节（§二之后 2.4）。凡是解释"为什么这么设计""我们刻意不做什么""这是部署信息"的句子，一律搬到需求文档里，界面上一个字都不留。

编号 禁止 原因
X4 禁止在创作台上出现步数、CFG、采样器、种子、Checkpoint 文件名、VAE 名等技术参数 用户看到也不知道怎么选；想调这些的人会直接去用 ComfyUI。管理台的配置区里可以有——那是给配置的人看的
X5 禁止让用户逐个字段打钩凑列（"宽勾一下、高勾一下、步数勾一下"那套） 配置成本高、容易漏勾（勾了宽忘了高就出半吊子状态）。勾的单位是节点：勾一个节点，它的参数成套进来
X6 禁止设计"全项目统一的一套档位" 每个工作流（不是每个能力——一个能力可以挂好几个工作流）的档位都必须单独定。图片和视频的档完全不同，套统一的必然有一半是废话
X7 禁止在创作台上出现"参数映射""节点 ID""字段名"这类内部词汇 用户不需要知道系统内部怎么对应。管理台里字段名可以显示（用小字灰字），因为配置的人需要核对
X7b 禁止在档位之外再给用户留"单独改某一个值"的口子（例如"高级设置""微调步数"） 那就退化成逐个调参数了。要调就把那一档整份拷贝改掉
X21 禁止把"宽 / 高 / 步数 / CFG"写死成固定几列或固定字段 这四个只是文生图常见的组合。音乐工作流没有宽高，绑了加速 LoRA 的工作流只该有步数和 CFG，语音只有音色和语速。写死等于给一半能力配了一堆废参数
X22 禁止在程序里按字段名做特殊判断（例如"如果字段叫 steps 就显示成 X 步""如果叫 width 就自动配 height"） 一旦按名字分支，就等于把字段名写死了。字段名要能随便换、随便加，程序只认"有个字段、它是什么类型、有个值"
X23 禁止给所有能力预置同一套节点/字段模板（"图片模板 / 视频模板 / 音乐模板"这种） 模板看着省事，但工作流一换就全错，还得手动改回来，等于多一层壳。节点只能从当前这个工作流里读出来再勾
X26 禁止把档位做成表格（一档一行，列是参数） 档位是列表：一行一档，只有名字 + 改动项数 +【编辑】+【删除】；点编辑才展开这一档那份拷贝的全部参数。做成表格，参数一多就横向撑爆
X27 禁止让"默认档"可改、可删、可改名 默认档就是原始工作流本身，只读。它存在的意义是给排查一个基准：默认档跑通了 → 问题在某一档的值上；默认档也跑不通 → 问题在工作流本身。一旦允许改它，这个基准就没了
X24 禁止因为"一个节点都没勾"就报错或拦住用户 语音合成这类工作流本来就可能只该有默认档。没勾 = 只有默认档，这是正常状态，不是配置错误。④ 显示空态、④ 的【添加】置灰就够了

2.1 参数控件：形态必须跟着类型走

编号 禁止 原因
X29 禁止把所有参数一律渲染成文本框 采样器、调度器、音色、分辨率都是枚举，给文本框等于逼用户背字符串，打错一个字母就整个任务失败。枚举必须给下拉或单选
X30 禁止把"是/否"参数渲染成文本框（让人填 true/false 或 1/0） 必须给开关。用户看到 true 只会问"这要填啥"
X31 禁止把多选参数渲染成下拉（下拉天然只能选一个） 数组类型的参数必须给多选勾选框，否则会把多值参数错误地降成单值
X32 禁止由我们"规定"某个字段该用什么控件（比如硬写"width 用数字框、某某字段用下拉"） 控件形态要读参数自己声明的类型（整数/小数/布尔/枚举及选项/数组/字符串）。表里没有的新字段按字符串处理即可，不要报错
X33 禁止在配置页上隐藏参数类型 每个参数旁边都要标出"这是哪种控件"。不标，配置的人会怀疑"这个我该填数字还是文字"，于是去翻工作流 json

2.2 哪些节点不该出现在可设置清单里

编号 禁止 原因
X28 禁止把提示词节点、上传参考节点、出片节点放进"可设置"清单（连复选框都不给） 改它们没有意义：提示词是用户在创作台现打的，每档写死一句没意义；参考图/音频数量不固定，要由服务端按用户上传的数量动态插入；出片节点只负责把结果拿出来。让它们出现在清单里，只会诱导人去填一个没用的值
X28b 禁止在前端管理页暴露"参考素材有几个"这种设置 数量由用户这次上传了几个决定，是运行时的事。管理页只需要选一个"这类素材绑到哪个节点"，剩下由服务端动态拼
X28c 禁止把"识别哪些节点是提示词/上传/出片"做成字段名清单（例如判断字段叫 text 就是提示词） 要按节点类型（class_type）判断，不是按字段名。别人家的提示词节点可能叫 prompt、t5xxl、*_text_encode，按字段名判断必然漏

2.3 提交与排队：两条路，不许混

编号 禁止 原因
X36 禁止让"普通生成"进队列（发送、再来一张、重试都一样） 普通生成是"马上要看到"的操作。塞进队列就变成盯着一条十几分钟不动的进度条，用户以为坏了。忙就直说忙，比默默排队好一百倍
X37 禁止在 ComfyUI 忙的时候仍然把普通生成提交上去（哪怕只是丢进 ComfyUI 自己的队列） 提交了就算"执行了"，用户会以为马上出片。要求是：忙 → 只提示，不提交、不排队
X38 禁止把队列生成做成"一次只能有一个"（排了一个就不许再排） 队列生成的用途就是批量跑高清。每点一次都要等上一次跑完，那"批量"两个字就没意义了。必须能连着点，排到队尾
X39 禁止让队列生成插到普通生成前面，也禁止在普通任务没跑完时接受队列提交 用户正在等的那一张是"当前的事"，队列是"待办的事"。顺序一反，用户会以为自己的片子丢了
X40 禁止"点了没反应"：任何被拦下的提交都必须说清是哪个任务在跑、跑到几成 只说"系统忙"等于没提示。用户需要知道"哦是刚才那张视频在跑，那我等它"
X41 禁止为队列单独做一个页面（"队列管理""任务列表"那一套） 队列的状态就三处：右栏一行状态、右栏一个清单、结果卡头部一个小标签。为此再开一页，等于承认主界面说不清楚
X42 禁止让【加入队列生成】换种子 队列生成的用途是"这张样片我要高清版"。换了种子就是另一张画，跟用户挑中的那张没关系了。同一批只能有一个种子，一路用到底
X43 禁止在卡片上罗列"共 N 个成品""档位 精细 / 默认"、也禁止贴归档路径 用户看这一批只关心两件事：这张用了什么种子、能不能再来一张。成品数和档位在卡头已有，路径在大图/下载里已有——卡底重复一遍，反而把真正有用的种子挤没了
X44 禁止在管理台提供"添加工作流""新建能力"这类入口（文件选择框、"＋ 新增"按钮、拖进来一个 json 都算） 能力和它挂的工作流是部署信息，只能写在 config.yaml 里。页面上点出来的东西：换个环境就没了、出了事也说不清是哪次点的。页面只做两件事——开/关、排档位
X45 禁止让"没挂工作流"的能力进入可编辑状态 没工作流就没有参数、没有档位，给一张空表单等于让人以为坏了，还会诱使产品去加"添加工作流"的后门。正确做法：列表里显示「未配置」，点进去只有一段说明——告诉人去改配置文件，页面上一个可填可点的控件都没有
X46 禁止除了【加入队列生成】以外的任何入口把任务排进 ComfyUI 队列 发送、再来一张、重试都是普通生成：ComfyUI 忙就只提示、不提交、不排队。队列是给"这张我很满意，出一版更高清的"用的，不能让随手点的发送也挤进去等 5 分钟
X47 禁止让"同时跑几个 / 超时 / 预览帧 / 队列上限"出现在页面上 一次只跑一个、不设超时（本机直连）、不收预览帧——这三件写死在代码里；队列上限写在配置文件里。这些连只读那一行都不必显示：不会变的事实摆在页面上，只会让人以为需要调
X48 禁止做"全局负面词" 没有需要"所有图片共用一段负面词"的场景。负面词就在各工作流自己的格子里，跟别的参数一样进档位表
X49 禁止在自检页逐个检查工作流（节点缺失、模型在不在、档位越不越界、出片节点认没认出来） 自检只做两项：ComfyUI 连不连得上、成果目录写不写得进去。工作流的毛病等真跑一次，ComfyUI 会直接点到具体节点具体那一格。预检做一份"节点对照表"，既慢又不准，还要跟着节点包天天维护

查"ComfyUI 现在有没有任务在跑"是允许的（读它的执行队列状态即可），这不等于 X15 说的"做显存守卫"——我们只是如实转达忙闲，不替它调度、不替它降档。

2.4 界面文案：只对使用者说话

判断标准一句话：这句话，一个只想赶紧出图的人看了有用吗？没用就删。

编号 禁止 说明与改法
X50 禁止在界面上解释"为什么这么设计"（"页面上不提供……是故意的""这一项不能关——归档是固定行为""这里是避免堆满目录"） 用户不关心设计取舍。只说你现在该做什么。反面例：「页面上不给加，因为这是部署信息」→ 正面：「要加工作流，改配置文件后重启服务」
X51 禁止出现只有做的人懂的词：部署信息、配置文件里的口径、写死、固定行为、后端、服务端、字段映射、归一、拷贝件、静默、回滚、幂等 用用户自己的说法：文件、配置、按钮、成品、上一版。管理台里可以出现"节点 / 参数 / 工作流"——那是配置的人必须认识的三样东西，且它们是 ComfyUI 里的原词
X52 禁止解释系统内部怎么实现的（"由服务端按数量动态接""等于把原始工作流深拷贝一份，写进复制件"） 用户只看到结果：勾几个节点右边就出几个参数；填好值点添加就多一档。实现细节一条都不写
X53 禁止在界面上写"不给 / 不许 / 不能 / 禁止"式说明 这类句子是写给开发者的约束。界面上要么直接把那个入口去掉，要么用中性陈述代替（"这一档是原文件，改不了"就够了）
X54 禁止一句话里塞两个以上因果链（"因为 A 所以 B，不然 C 会 D，如果要 E 就得 F"） 折成两句短话，或者只留最需要用户知道的那半句。卡片和面板的说明文字，一行不超过 20 个字最舒服
X55 禁止把"原型 / 演示 / 模拟"写进正式界面的按钮和提示里 只有开发自己用的调试入口可以说"演示版不做真下载"；正式交付时这些字样全部清除
X56 禁止让文档里的界面示例和实际画面脱节 文档插图里的每一句话，都必须能在真界面上原样找到。原型改了口径，插图同步改；插图里出现"挂载的工作流（配置文件里）"这种画面上根本没有的区块，开发照着做就会把它造出来——文档插图就是开发眼里的需求

X50~X56 的用法：写界面文案时先问一句"这句话是给用它的人看的，还是给做它的人看的"。后者一律搬进文档，不要留在画面上。改完文案后用敏感词扫一遍页面（部署 / 写死 / 固定行为 / 不给 / 原型 / 来自配置文件 / 设计），有命中就重写。

三、配置与存储：只维护当前状态

七、一句话总结

这个应用只做一件事：把 ComfyUI 的工作流包装成"会用斜线技能的 AI 能直接点的一道菜"。

界面要极简（描述框 + 档位），配置要极简（选文件 + 勾几个节点 + 填值点添加），存储要极简（单配置文件 + 一堆工作流拷贝），接入要唯一（斜线技能）。

档位里有哪些参数，永远是这个工作流决定的，不是程序决定的（X21~X33）。这一条弄反了，每加一个新工作流都要回来改代码，那就白做了。

配置页只有一件事要做：让用户看清节点、勾出该给用户的那几个、再给它们造几档。 造档的方式是"复制一份工作流"，不是"填一张表"——这样每一档天然就是一份能直接发出去的工作流，不需要运行时再拼。

原始工作流永远是默认档，永远是只读的基准（X27 / X35）。所有"改"都发生在拷贝上。

普通生成忙了就拦住，队列生成才允许堆积（X36~X41）。这两条反过来，用户要么在等一张本该 6 秒出的图，要么得守着一张一张点高清。

一批一个种子，队列只换档位不换种子（X42 / X43）。种子一换，"再来一版高清的"就变成了"再画一张，随便吧"。

任何让上述四件事变复杂的需求，先回到这一章对一遍。

第 08 章手机端（同一套功能，另一种摆法）

一、原则：只是摆法不同，功能一个不少

窗口窄到 820px 以下就切到手机布局。切换的只有"东西放在哪"，不是"能不能用"：同一个服务、同一份状态、同一批接口，刷新前后不丢任务，手机上点了电脑上能看到。

为什么不做成两套页面：两套页面意味着两套 bug。这里只有一套 DOM，靠一条媒体查询换排布——手机上出问题，桌面上同样能复现，好查。

三、11 条验收（手机上逐条点一遍）

#点哪里应该看到

9档位表底部「返回列表」在左、「保存」在右

四、手机上明确不做的事

  • 不做独立的手机页面、不做 App 套壳——一套页面换排布，问题好复现。
  • 不让档位表横向滑动看列——宁可换行，也不引入"横向表格"这种手机上必翻车的交互。
  • 不在手机上开放「批量管理能力」——能力清单本来就不在页面上改，手机上更不给入口。

Q4　这次哪几处是我的建议，你可以否决

建议理由否决的后果
页面由后端进程直接发出（只跑 1 个进程，不是 2 个）前端就是一个静态文件夹，单开一个服务只多占几十兆内存多一个进程和一个故障点，对你"把资源留给 ComfyUI"没有好处
加一个"试跑"按钮映射表填错了，只有真跑一次才发现。试跑把所有问题挡在配置阶段用户点发送时才失败，且你不知道是"工作流问题"还是"参数问题"
挑工作流的条件里默认"报错"而不是"随便挑一个"早期工作流不全，宁可明确说"这种情况还不支持"，也不要跑错流程让人等 5 分钟用户看到的是"出了个莫名其妙的图"，比报错更困惑
能力清单做得很短（不是完整参数说明）清单每次都要被 AI 读进上下文，越长越慢。短才快AI 每次思考多花 1~3 秒，抵消掉这一层的意义
16 个能力入口先建好、标"未配置"你能看见"还差什么"，体系是完整的；灰色不碍事也可以完全不显示，但你就失去了"还差哪些"的清单感

Q5　还有 3 个问题需要你确认

① 工作流 json 放哪儿？放在应用自己的 workflows 目录（换机器整包拷走），还是直接指向 ComfyUI 的工作流目录（改完不用另存）？两种都支持，只是默认值不同。
